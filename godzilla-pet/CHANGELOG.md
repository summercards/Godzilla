## 一、Boss 血量：从"写死的基数"改成"按目标击杀时长反解"

### 为什么原来的血条没有意义

改前 `TYPES.sentinel.hp = 2200`，然后 `enemy()` 再乘 `P.Ke(district)`。
2200 是个拍出来的数，它和"巨兽几级、投了多少力量/吐息"完全无关，
于是后期必然出现"越打越快"。2026-09-20 用无头沙箱实打一场
（`.workbuddy/_boss-ttk.cjs`，数帧数到 Boss 不再 alive）：

| 档位 | 巨兽实力 | 旧血量 | 实测击杀时长 |
| --- | ---: | ---: | ---: |
| LV10 / 第 4 区 / 全投力量 | power 455 · atomic 191 | 2200×Ke(4) | **47.7 s** |
| LV40 / 第 12 区 / 全投力量 | power 3194 · atomic 393 | 2200×Ke(12) | **15.1 s** |
| LV120 / 第 27 区 / 全投力量 | power 18104 · atomic 773 | 2200×Ke(27) | **15.1 s** |

后两档时长一模一样 —— 因为它们的时长**等于尾扫的冷却**，正好一次尾扫
7027 伤害就把 Boss 秒了。也就是说血条到后面根本没参与运算，
"没挑战"不是数值偏低，是**数值不再被读**。

### 现在的口径

Boss 是唯一"必须打赢才能继续"的实体，而这个产品**没有血条、没有死亡、
不引入失败状态** —— 所以它不能被设计成打不过。血量只能锚在巨兽自己的输出上，
才能让每一档等级、每一种加点都稳定落在同一段时间里：

    bossMaxHp() = max(2200, round(bossRefDps() × 60))

    bossRefDps() = ( power()   × (2.8/13.68 + 2.2/16.65)
                   + atomic()  × (2.6/28) ) × BOSS_TTK_CAL

只取**真能打到关底**的三个动作。关底停距 340~520px（由体型与挡路建筑决定）：
爪击 reach 135 够不着、长啸 850 够得着但权重极小、略去。权重一律写成
「一次伤害 ÷ 一轮周期」，每一项都由别处的既有常量推出来，不新造数字：

| 动作 | 权重 | 出处 |
| --- | --- | --- |
| 重踏 | `power × 2.8 / (12s 冷却 + 1.68s 动作)` | 技能表 |
| 尾扫 | `power × 2.2 / (15s 冷却 + 1.65s 动作)` | 技能表 |
| 吐息 | `atomic × 2.6s 有效窗口 / 28s 冷却` | 技能表 |

`BOSS_TTK_CAL = 0.5` 是与实测对齐的标定系数：上面算的是"理想站桩输出"，
实际还有走位、被挡路建筑拖住、被 Boss 重拳打断（`p.stagger` 会冻住动作计时），
打折之后才落地。`BOSS_TTK_TARGET = 60` 是目标击杀秒数。

> ⚠️ **改上面任何一条冷却 / 倍率 / 标定系数，必须重跑 `.workbuddy/_boss-ttk.cjs`
> 重新标定。** 这条写在 `game.js` 的注释里，和公式挨着。

### 实测确认

| 档位 | 新血量 | 新实测击杀时长 |
| --- | ---: | ---: |
| LV10 / 第 4 区 | 5,128 | 61.3 s |
| LV40 / 第 12 区 | 33,372 | 50.6 s |
| LV120 / 第 27 区 | 185,078 | 52.1 s |

三档都收进 50~61 秒，且**不再等于任何一个技能的冷却** —— Boss 血量重新参与了运算。

### 存档兼容

存档快照里原来只存 `hp`、没存 `max`，改完后 `max` 会随等级重算 →
按绝对值恢复会让读一次档血条跳一下。所以：

- `worldSnapshot()` 给 Boss 快照加上 `max`（`{max:e.max, introDone, introStarted, introTime}`）；
- 恢复时按**比例**：`e.hp = e.max × clamp(s.hp / oldMax, 0, 1)`；
- 老档快照里没有 `max`，用改动前的公式把它换算成比例：
  `bossLegacyMax(district, village) = 2200 × Ke(区) × (村庄 ×0.6)`。

`BOSS_HP_BASE = 2200` 因此有双重身份：血量的下限，同时也是旧档迁移的换算基准。

## 三、换场：电视转台式的全屏雪花，取代硬切

原来"世界替换"和"画面替换"在同一帧发生：Boss 落地 → 直接 `generateWorld()`
→ 下一区第一帧就顶上来。观感是硬切，看着像画面跳了一下。

现在雪花从 **Boss 倒地那一刻**（`defeat()` 把它推入 `'falling'`）就开始爬升，
世界替换仍发生在 `BOSS_FALL` 那一拍 —— 只要它落在 `[rise, rise+hold]` 区间里，
替换那一帧屏幕就被雪花**完全糊满**，玩家看不到任何"换"的动作。

    SCENE_SWITCH = { rise: 1.6, hold: 1.2, fall: 0.75 }
    契约：rise ≤ BOSS_FALL(=2.4) ≤ rise + hold      即 1.6 ≤ 2.4 ≤ 2.8 ✔

这三条数的大小关系就是这条链上真正的契约，被 `tv/tests/scene-switch.test.cjs`
用一个会失败的断言钉住。单独把 `rise` 拉长到 `BOSS_FALL` 之后、
或把 `hold` 压到 0，都会让"硬切"重新露出来 —— 而那种时候画面只是看起来
"有点闪"，不报错，正是最该由断言盯住的一类回归。

配套改动：

- 原来 `updateEnemies` 里写死的 `2.4` 提成常量 `BOSS_FALL`（世界替换与雪花共用同一个数）；
- `sceneSwitchAlpha(t)` 是纯函数、不碰任何状态，换场那一拍是否"遮满"由它判定；
- `noiseGrain(a,b)` = `sin` 哈希，**不用 `Math.random`** —— 画面噪声不该消耗熵源、
  也不该随帧率抖成另一张图（同项目"外观只用 hashSeed+mulberry32"那条纪律）；
- 雪花画在画布上，而机位条 / 字幕 / 滚动条 / 横幅是 DOM、`z-index` 高于画布 ——
  所以 `#stage.scene-switching` 让这一组浮层整体 `opacity:0` 让位，
  雪花散开后再由 `banner()` 把新区域的横幅摆回来；
- `drawSceneSwitch()` 盖在 `render()` 末尾，**转台与直播两态都覆盖**
  （`out` 与 `channelCtx` 各画一次）。

## 五、两侧机位条：从「中心对齐」到「贴屏幕最上沿」（同一句反馈的两轮解读）

### 第一轮：病灶是一条纯 CSS 的相互作用，不是谁写错了一行

主人圈了两块说「这两个 ui 向上对齐」。用探针量四个盒子的顶边，真相很反直觉：

| | 左组「LIVE + 第一章 · 大阪」 | 右组「AIR CAM 07 + 时钟」 |
| --- | ---: | ---: |
| 改前高度 | **38.9** | **33.1** |
| 改前盒子顶边 | y=108（= 红徽章涂色顶边） | y=110.9 |

左组高出来的 5.8 来自 `<b>LIVE</b>` 徽章的 `padding:2px`（竖向），
而容器是 `align-items:center` —— 于是两块**中心对齐**，左块顶边反而
比右块高出 (38.9−33.1)/2 = **2.9 逻辑像素**。实心红块的顶边对着旁边一行
纯文字，这点差值一眼就能看出"没对齐"。

两侧的**文字本身是齐的**（墨迹都在 `y=114.1` 起），不齐的只有红块那个实心边 ——
这也是为什么单看文字查不出问题。

### 修法：两处一起改，缺一处都会回退

1. `.camera-top` 的 `align-items:center` → **`flex-start`**；
2. 徽章去掉竖向 padding、`line-height:1`（高 18px = 字号）。

**第 2 条不能省，这是本次最值钱的一点**：左块比右块高时，左块自己就是
最高的那一项，`flex-start` 与 `center` 算出来的结果**完全相同**（左块顶边
都等于容器顶边）。真正把红块顶边顶上去的是徽章自己的竖向 padding ——
只改容器的话，量出来的数字一个字节都不会变。

两条都到位之后：

| | 改前 | 改后 |
| --- | ---: | ---: |
| 红徽章涂色顶边 | y=108 | **y=111.3** |
| 右侧文字墨迹顶边 | y=114.1 | **y=111.2** |
| 两者差 | 6.1 | **0.1** |
| 左 / 右组高度 | 38.9 / 33.1 | 33.1 / 33.1 |

像素剖面复核（`.workbuddy/_c2-align.cjs` 出的截图 + 逐行统计）：
`LIVE` 的白字与右侧 `AIR CAM` 文字的**首行都在 py 94**；
红块比文字首行只高 1 个设备像素，块内上下各留 1~2px 红边，**字没有贴边**。
实心块本就该略微包住文字 —— 这就是"顶对齐"在实心块 + 纯文字这一对上的正确形态。

> 代价（明确接受）：`LIVE` 徽章从 26.5 高变成 18 高（CSS px），
> 也就是视觉上小了一圈。这是**为了让它的顶边能和旁边那行文字对上**必须付的 ——
> 一个带竖向 padding 的实心块，顶边永远会比同一行纯文字高出去一截。

### 第二轮：主人要的是**纵向位置**，不是两条之间的内对齐

第一轮改完，主人看过截图说的还是「这两个**还是在下面啊**，没有在屏幕的上方对齐」。
**答错题了。** 主人圈那两块是为了指出"这两块所在的位置"，
不是要它们俩互相对齐。`15%` 在 1280×720 里是 `y=108`，落在画面上方 1/7 处，
看着就是"悬在半空"。

改法只有一处：`html:not(.panel-view) .camera-top{top:15%}` → **`top:0`**。

#### 怎么确认"改前改后"的差别真的来自这一个声明

主人第一张反馈图是自己截的，两张图分辨率与窗口尺寸都不同，拼在一起"看起来"
对不齐是**没法归因**的。所以做了一个受控 A/B
（`.workbuddy/_c3-ab.cjs`）：同一个探针窗口、同一份存档，
先按源码当前状态抓一张，再**注入一条 `top:15% !important`** 抓第二张 ——
两张图之间只差那一个声明。

| | 改前（`top:15%`） | 改后（`top:0`） |
| --- | ---: | ---: |
| 机位条行盒顶边 | y=108 | **y=0** |
| 左组矩形 | y 108 ~ 141.1 | y 0 ~ 33.1 |
| 右组墨迹盒 | y 108 ~ 141.1 | y 0 ~ 33.1 |
| 位移 | — | **108 逻辑像素** |
| 左右组横向范围 | x 25.6~307.9 / 960.4~1254.4 | 不变 |

#### 为什么不写成 `2%` 之类，而是干脆写 `0`

写 `0` 的好处是**不依赖窗口尺寸**：百分比要跟着画布高度重新推算，
`0` 是屏幕的物理边界，换档位也不会漂。代价是要确认"不会撞上推图条"：

- 行盒占 `y 0~33.1`（18px 字号 × line-height 1.25 = 22.5px 行盒 + flex 拉伸），
  推图条背板是 `y 20~40` —— 行盒底部 13px 落在背板的纵向区间里。
- **但行盒不是眼睛看到的东西。** 推图条横向占 `x 354~926`；
  左组文字墨迹到 `x=307.9` 就结束（**留 46.1px**），
  右组墨迹从 `x=960.4` 才开始（**留 34.4px**）——

## 一、为什么原来会砸在巨兽身上

`armBossIntro()` 原来写成：

```js
if (… && Math.abs(e.x - p.x) > BOSS_IN_RANGE) e.x = p.x + NODE_LEAD;
```

那个距离判据本意是"设过了就别再设"（设完 Boss 就在 p.x+520，差值必然 ≤ 阈值），
但它顺带把"Boss 本来就在巨兽附近"这种情况也挡掉了 —— 而闸门锁存之后继续挂机，
巨兽走过节点一小段、Boss 仍守在节点上，差值 312px < 580，**判据不成立 → 不重定位
→ Boss 原地砸下来**。实机存档就是铁证：`world.x=4722`、`boss-sentinel.x=4410`。

现在改成按"当前位置是否就是登场位"判断，与 Boss 原先站在哪无关；演出已经开始
（`introStarted`）就不再干预，免得把起跳中的 Boss 拽回去。

## 二、登场位：按屏幕位置反解，而不是写死世界距离

第一版修法是把世界偏移从 520 调到 640。但镜头缩放 `s = sceneZoom×0.8` 随体型
从 **1.04（幼兽，镜头拉近）** 降到 **0.51（灾厄体，镜头拉远）**，同一个世界距离在
屏幕上会漂近一倍：

| 等级 | 体型 | s | 写死 640 时的画面占比 |
| ---: | ---: | ---: | ---: |
| 1 | 0.34 | 1.04 | 87% |
| 50 | 0.76 | 1.04 | 83% |
| 160 | 1.60 | 0.51 | 68%（缩回画面中间） |

所以改成按**目标屏幕位置**反解：`世界偏移 = (目标屏x − 巨兽屏x) / s`，
`巨兽屏x = p.x − cameraTarget()`（相机稳态值，与 camera 是否收敛无关；读档那一帧
camera 还是 0，用 camera 会算出负数）。结果夹在 `[120, BOSS_IN_RANGE−120]`。

`BOSS_SCREEN_X = 0.80`，实测标定后**全等级恒落 80%**（画面右侧三分之一的中段）：

| 等级 | 1 | 25 | 50 | 75 | 100 | 160 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 世界偏移 | 580 | 539 | 508 | 555 | 595 | 910 |
| 画面占比 | 80% | 80% | 80% | 80% | 80% | 80% |

`BOSS_IN_RANGE` 580 → **1100**，作为登场位上限。这条不变式必须守住：登场位一旦
越过触发半径，`updateSentinel` 的接近判据就不成立 → 演出永不开始 → 玩家只看到
"点了没反应"，而按钮已经永久禁用 = 死档。

## 一、火焰 / 烟尘：锁在 25 级那一刻，不再跟体型走到底

改前是 `clamp(bodyScale() * (1+jitter), .25, 1.25)` —— 上限 1.25 与体型上限
`growth.CEIL = 2.24` 其实还是同一条曲线，怪越长火越大，只是封顶低了点。
改后把**上限本身**变成"25 级那一刻的体型"，从 `EPOCHS` 推，不写数字：

| 等级 | 裸档体型 `bodyScale` | 改前火焰缩放 | 改后火焰缩放 |
| --- | --- | --- | --- |
| 1 | 0.34 | 0.34 | 0.34 |
| 15 | 0.48 | 0.48 | 0.48 |
| **25** | **0.58** | **0.58** | **0.58**（基准，一字不动） |
| 50 | 0.76 | 0.76 | **0.58** |
| 100 | 1.00 | 1.00 | **0.58** |
| 160 + 满天赋突变 | 2.24 | 1.25 | **0.58** |

```js
const FX_LOCK_LEVEL = P.EPOCHS[1].min;                              // 25 = 亚成体起点 = 满 1 倍
const FX_SCALE_MAX  = Growth.bodyScale(FX_LOCK_LEVEL, null, null, P.EPOCHS);   // 0.58
function fxScale(jitter){ return clamp(Math.min(bodyScale(), FX_SCALE_MAX) * (1+(jitter||0)), .25, FX_SCALE_MAX); }
```

三点必须记住：

- 25 级以下照旧跟着缩小（小巨兽配小火），**25 级那一刻的取值与改前完全相同** ——
  这正是"参考 25 级锁死"的字面意思，不是把火整体缩小。
- 上限取**裸档**（不带天赋/突变）的大小。这是一条封顶线，不该随玩家加了多少突变往上飘。
- `render` 的火焰与 `update` 的烟尘**只走 `fxScale()` 这一个出口**（原来是两处

  并让测试钉住"没有第二处 `clamp(bodyScale()*…)`"。

能拖。柜子在视口里是 1088×625（视口 1120×736），上下各留 55px、左右各 16px，
× 0.46 缩放后左右不足 10 屏幕像素；再叠上独立声明过的 `header`（46px 台标条）与
`footer`（38px 页脚）两条拖动区 —— 能拖的就只剩"上下两条"。压住画面正中，
也就是这个窗口的主体，一动不动。

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 柜外留白（`body`） | 可拖 | 可拖 |
| 台标条 / 页脚 | 可拖 | 可拖 |
| **侧栏 / 画面 / 机身** | **不可拖** | **可拖** |

## 二、改法：柜体整块 drag，可点控件逐个 no-drag

拖动判定按**命中点所在的最近一条显式声明**算：祖先里有一个 `drag`，该范围内没被
`no-drag` 挡住的像素就都能拖。所以反过来把控件列出来最直接 —— 这份画面里需要
保留点击的只有 `button` / `select` / `input` / `label` 四类。

## 三、继承属性的坑：面板窗口必须显式压回 no-drag（本次最值钱的一条）

`-webkit-app-region` 是**继承属性**。证据就在审计输出里：`.tv-menu` 自己没声明过
任何值，而 `REGION` 行读到的是 `dock=drag`（继承自祖先）。

于是"让 `.shell` 可拖"会顺着继承渗进**面板窗口**那份页面 —— 面板窗口整页就是
`.shell`，被 `drag` 裹住之后滚动条与滚轮都会被吞掉。而改动前 `.shell { no-drag }`
是**全局**规则，面板窗口整页恰恰是 `no-drag`，所以旧行为必须显式重建：

```css
html:not(.panel-view) .shell { -webkit-app-region: drag; }    /* 电视：柜体整块可拖 */
html.panel-view .shell     { -webkit-app-region: no-drag; }  /* 面板：显式压回去 */
```

`panel-view` 只由 `panel-preload.js` 加在面板窗口的 `documentElement` 上，电视窗口
永远不带这个类。

## 四、验证：把"点了没反应"变成一条会失败的断言

拖动区的故障现象是**"按钮点了没反应"，两端都不报错** —— 只看 CSS 文本看不出
"这个控件被拖动区吞掉了"。所以补了两层检查：

| 层 | 位置 | 判据 |
| --- | --- | --- |
| 结构 | `tests/tv.test.cjs` | 拆规则块逐条断言：柜体 `drag`、面板 `no-drag`、四类控件 `no-drag`、`management-screen` 只限电视窗口 |
| 实测 | `build/tv-shot.cjs` 的 `REGION*` 行 | 真窗口注入后沿祖先链回算每个可见控件的有效归属，落在 `drag` 上直接断言失败 |

实测输出（2026-09-18）：

```

面板窗口  REGION*  controls=19  swallowed=[]  shell=no-drag  shellDecl=no-drag
```

配套：`npm test` 133 项 / 125 过 / 0 失败 / 8 项 macOS 跳过。

## 五、已知代价（明确接受）

拖动区**不再把鼠标事件派发给页面**，所以画面本体上的 `pointerdown` 也不再触发。
电视窗口里画面本体本来没有可点功能，唯一挂着的是音频解锁那一行
（`document.addEventListener("pointerdown", …audioInit)`）—— 而它只在"没静音"时
才做事，那种状态必然点过观测面板里的「开启现场声音」（那次点击本身就会解锁），
所以实际影响为零。新开声音的路仍在：设置页的「开启现场声音」按钮与换台按钮都是
`no-drag`，照点照用。

右键菜单（`popupControlMenu`）由主进程处理，本次未实测在拖动区上的表现 ——
托盘菜单是同一批操作的同源入口，若发现右键在柜体上不出菜单，回报即可。

## 四、加点 / 变异按钮"按下去没反应"

病根和第三节同一类：**判据没错，但电视窗口里那块门牌从来不刷新。**

`renderGrowthPanels()` 在电视窗口里一次都不会跑 —— `tv-preload.js` 的
`guardMainPanel()` 用 MutationObserver 把 `#management` 永久按住 `hidden`，
`hud()` 里那句重绘的守卫 `if(!$('management').hidden)` 于是恒为假，剩下的触发点
只剩"某个命令成功执行之后"那一次。于是 `#assign-*` / `#buy-*` / `#rollEvo`
带着**上一次成功操作那一刻**的 `disabled` 活着：用光点数被置灰 → 之后升级再把
点数发回来 → 按钮仍然是灰的。而 `panelCommand()` 第一句就是
`if(!el||el.disabled)return null;`，面板点过来的命令被**静默丢掉，两端都不报错**。

实测（`.workbuddy/probe-growth-gate.cjs`：隔离 userData + 把真面板窗口一起开起来同框对照）：

| 时刻 | 加点机会 | 加点按钮（面板 / 电视） | 发一条 `assign-power` |
| --- | --- | --- | --- |
| 改前 · 用光点数后 | 0 | disabled / disabled | — |
| 改前 · 升级把点数发回来 | 1 | **enabled / disabled** | 返回 null，1 → **1（不动）** |
| 改后 · 升级把点数发回来 | 1 | **enabled / enabled** | 1 → **0（生效）** |

修法：判据抽成一份 `statGate(k)`，门单独用 `syncGrowthGates()` 挂在 `hud()` 的
200ms 心跳上 —— 它只跟数值走，跟"面板是否可见"无关。`#buy-*`（核能购买）受害最重，
因为核能每时每刻都在变，它几乎必然停在"买完那一刻"的灰。

`tv/tests/growth-gates.test.cjs` 三条断言 + 变异自测：删掉心跳调用、把门挪进
"面板可见"守卫、在 `renderAssignPanel` 里另抄一份判据 —— 各自都会红。

## 五、渲染进程死掉之后，窗口必须能自己醒过来

排查第四节时量到的一个既有缺陷（当时为了对照，把两个窗口的渲染进程分别杀了一次）：
`main.js` 的 `app.on('render-process-gone')` **只记一条日志，什么都不重建**。

于是渲染进程一死，那个 BrowserWindow 就永久白板：面板的渲染进程死掉后 `panelWin`
对象还在，`openPanel()` 发现它没被销毁就只 `send('panel:select')` + `show()`，
叫回来的永远是一块白板；托盘里也没有"关闭面板"这一项 —— 玩家只剩重启桌宠一条路。

改成重建一次（`contents.reload()`），并记一条「正在重建渲染进程」；同一个 contents
再崩就放弃，别让确定性崩溃变成后台死循环重载。`clean-exit` 明确跳过 —— 那是正常
关闭，复活它会把正在销毁的窗口拽回来。reload 本身是安全的：一切进度都在存档里，
重新认档走的是同一条 `tv:saveBoot` 握手。

验证（`.workbuddy/probe-render-revive.cjs`，只在自己那个隔离实例上做，杀之前逐个
核验父进程 PID）：杀掉两个渲染进程后 9 秒内电视与面板两个页面都恢复、日志里
「渲染进程退出」2 条对应「正在重建渲染进程」2 条。

# 2.5.0 · 控制按钮与观测面板都搬到窗口外

画面里的功能按钮看不清也点不准，这一版把按钮和面板都搬到电视窗口外面。

## 起因：0.46 倍的缩放

电视窗口的布局视口恒为 1120px，中档窗口只有 520px 宽，缩放系数 0.46。
画面右上角那排功能按钮（强化 / 技能树 / 档案 / 设置）的字本来 12px，
落到屏幕上只剩 **5.6px**。

这不是"按钮做得不够大"，而是**任何待在被缩放画面里的 UI 都不可能看清**。
所以解法只有一条：让它离开缩放。

## 改了什么

- 新增 `dock.html` + `dock-preload.js`：一个 64px 的像素风按钮，
  住在独立窗口里，所以它有多大就是多大。粗颗粒的做法是全部用整数像素描边、
  阴影一律不带模糊（`6px 6px 0`），图案画在 6×5 栅格上再整数倍放大。
- 新增 `tv:panel` 通道：`tv-preload.js` 用 `MutationObserver` 盯住
  `#management` 的 `hidden`，面板一开一关就上报主进程。
- `main.js` 新增控制按钮与面板窗口的创建、跟随、开关：
  - 按钮贴着电视窗口外侧，窗口一动就重新摆；左边顶到屏幕边缘翻到右侧，
    两边都挤不下时退到窗口内部左下角（宁可压住一点画面，也不能让按钮跑到屏幕外）。
  - 点按钮 → **另开一个面板窗口**（`min(1, 可用高度 / 736)` 定缩放、居中），
    不是把电视窗口放大。电视那边从头到尾不动。
  - 面板关掉 → 收走窗口，按钮继续贴着电视。
  - 窗口收起/展开时按钮跟着一起收放；改档位或回位时重新摆。
- 新增 `panel-preload.js`，面板窗口的存档层。它跑的是**第二份 game.js**，
  所以必须和电视那边分工明确：
  - **只读**：`setItem` 只更新内存、绝不落盘。落盘由电视窗口独占 ——
    两个实例都写文件的话会互相覆盖，谁后写谁赢，另一个还拿着旧数据继续跑，
    而磁盘上看不出任何异常。
  - **操作转发**：面板里的点击/变更按元素 id 转给主进程，由主进程在**电视窗口**
    里执行同一个元素。游戏的权威状态在电视那边，面板只是个遥控器；
    少了这一步，面板里的强化就只是"改了个内存数字给人看"。
  - 转发跳过 `open-*` 入口，否则电视窗口也会跟着弹一个面板出来。
- 新增 `TV_HIDE_DOCK_CSS`：藏掉画面里那排原按钮。**这是整个工程唯一改变
  画面呈现的注入**，理由见下。

## 关于那条唯一的例外

藏按钮确实改了画面的外观，所以它被单独拎出来管：

- 和 `TV_DRAG_CSS` 分成两个常量，绝不合并 —— 合并了的话
  "注入不改变呈现"这条不变式就永远说不清。
- 新增两条断言：隐藏规则里只许出现 `display`（出现 `color` / `font` /
  `width` / `opacity` 之类就失败）；拖动规则里不许出现 `display`。
- 想还原只需要删掉这一条规则，画面本身没有任何残留改动。

之所以用注入而不是去改 `tv/`：`tv/` 依旧一个字节都没动。

## 本次验证

在真实 Electron 里跑通了整条链路（用 `GNN_DEBUG_PORT` 开远程调试端口，
连的是用户真正会遇到的那条路径）：

| --- | --- | --- | --- | --- |

两个窗口**尺寸相同、成套摆放**（面板贴在电视窗口外侧），内容 1:1 对齐电视档位。

- `npm test` **46 项通过**（growth-system 10 / tv 16 / save-store 20）、0 失败，
  另有 8 项在非 macOS 上跳过。

现在只剩一条线，存档自然要跟着画面走。

难点是**画面不能改**。做法是在外面劫持：

- 新增 `tv-preload.js`。画面读写存档的地方总共只有两处
  （启动时同步 `getItem`，每 5 秒 / 切走 / 卸载时 `setItem`），
  接管层只把这**一个键**的读写换接到文件，其余一律原样放行。
- 三条硬约束，都是踩过才知道的：必须是 preload（画面**同步**读档，替换得赶在
  它任何脚本之前）；`contextIsolation` 必须关掉（隔离世界里 `Storage.prototype`
  是另一份对象）；读必须保持同步（异步会让画面先拿新档把世界建起来，
  再被迟到的文件覆盖成第二次初始化）。
- 退出路径用同步 IPC（`sendSync`）：`pagehide` 那一刻没有"稍后"，
  异步回调根本发不出去。日常写入走异步 + 1 秒防抖，不阻塞渲染帧。
- 存档文件从 `pet.json` 改名 `tv.json`，格式变成外面一层桌宠封装
  `{ version, payload }`，`payload` 是画面自己那份 JSON 字符串，原样透传。
- 迁移：文件里没档而 localStorage 里有 → 自动搬一次。
  目录里遗留的旧 `pet.json` 不会被读也不会被删（格式对不上，安静走新档）。

**这次改动最要紧的一条测试**：两边只靠一个字符串常量关联
（`tv/game.js` 的 `SAVE` ↔ `tv-preload.js` 的 `KEY`）。对不上的话接管会
**静默失效** —— 画面照常跑、照常显示"进度已保存"，只是写回了 localStorage，
导出备份时拿到空文件，全程零报错。所以 `tests/tv.test.cjs` 加了四条断言，
不是断言"代码里有这个字符串"，而是把两边读出来对比，并在断言消息里写清后果。

# 2.3.0 · 桌宠主线化与文件存档

从这一版起，仓库以桌宠为唯一主线；原先与它并列的网页版降级成它播放的画面
（`tv/`），不再是需要单独维护的第二条产品线。

## 目录

- `godzilla-shinjuku/` → `godzilla-pet/tv/`。迷你电视不再依赖项目里另一个同级
  目录，`godzilla-pet` 单独拷走就能跑，这条老限制随之消失。
- 单文件离线版从根目录移入 `godzilla-pet/dist/`，与生成的 `.app` 放在一起，
  都算发布产物。
- 根目录的历史文件移入 `archive/`：`雨夜新宿.html`（与 `巨兽都市-挂机直播.html`
  逐字节相同的重名副本，同 MD5）、`雨夜新宿-游戏与源码.zip`（真正的旧街机版）、
  `巨兽都市-挂机版与源码.zip`（已被目录内容取代的旧全量包）。
- 版本号统一到 2.3.0：`package.json` 与 `.app` 的 `CFBundleShortVersionString`
  以前停在 1.0.0，与 `tv/CHANGELOG.md` 里已经走到 2.3 的画面版本号不一致。

## 存档

存档从渲染层的 localStorage 改成主进程管的文件：
`<userData>/save/pet.json`。

- 新增 `save-store.js`：写临时文件 → fsync → 主档改名成备份 → 临时文件改名成
  主档。两次改名都是原子的，因此任何时刻磁盘上至少有一份完整可读的档；
  主档读不出来时自动回退备份。不依赖 electron，目录由调用方注入，可单独测。
- 新增周期落盘：主循环按真实墙钟累积，每 5 秒写一次。**在这之前桌宠没有任何
  自动存档** —— `save()` 只在「页面隐藏」「暂停/静音」「退出」时被调用，
  而挂机游戏恰恰长期处于"窗口可见、无人操作"的状态，几小时不写盘是常态，
  断电或强杀就会丢掉那几小时。
- 新增退出握手：主进程在 `before-quit` 里等渲染层同步写完最后一次进度才真正
  退出（最多等 800ms）。`pagehide` 也改用同步 IPC，因为那一刻没有"稍后"。
- 新增「存档」菜单（托盘与右键共用）：打开存档文件夹 / 导出备份 / 从备份导入 /
  重置存档。导入前先校验来源文件，坏文件不可能把好档顶掉；导入与重置都会先确认。
- 新增一次性迁移：首次启动时若文件存档不存在而 localStorage 有旧档
  （键 `gnn-pet-v1`），自动搬进文件并提示一次。浏览器预览没有主进程时，
  仍回退到 localStorage。
- 存档新增两个长期字段：`bornAt`（第一次见面）与 `sessions`（累计启动次数）。
  老存档没有 `bornAt` 时用累计陪伴时长倒推（出生 = 现在 − 陪了多久）。
  版本号保持 1，老存档照常读。

## 其它

- 异步读盘之后，「页面加载完」不再等于「宠物已经在了」。新增
  `window.__petDebug.ready` 供 QA 脚本判断世界是否建立，`qa-shot.cjs`
  改为轮询它而不是猜一个 sleep 时长。
- `qa-shot.cjs` 注入等级不再改 localStorage 再重载（还要把 `setItem` 换成空函数
  以防止卸载回写覆盖注入值），改为建一个临时存档目录、先写好目标存档再打开窗口。
  少了两步绕路，而且顺便验了真实的文件存档路径。工具只用临时目录，
  绝不碰用户自己的存档。
