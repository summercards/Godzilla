# 资产规范 v1（约束文档）

> 本文是**强制约束**，不是建议。其中大部分条款已经被 `tv/tests/assets.test.cjs`
> 变成可执行断言 —— 违反规范会让 `npm test` 直接红。
> 框架说明见 [怪物形态框架.md](./怪物形态框架.md)。

---

## 1. 总原则

1. **一个事实只存一处。** 路径只写在 `tv/assets/asset-index.js`；
   骨骼结构只写在 `source/parts.json`（然后生成 `rig.json`）；
   "哪个突变改哪个轴"只写在 `tv/appearance.js`。
2. **手写物与生成物必须分开。** 生成物文件头会写明来源，**不许手改**（见 §6）。
3. **命名即契约。** 目录名与代码里的 id 必须逐字符相同，不做大小写或拼写"美化"。
4. **资产改动必须能被测试发现。** 加资产要同步登记，否则测试报"目录里有未登记的东西"。

## 2. 目录结构

### 2.1 总览

`tv/assets/` 只放游戏运行资产。根目录 `assets/`（仓库根）是 Electron 图标，
与本规范无关，不要混。

```
tv/assets/
├─ asset-index.js                  ← 资产位置与清单的唯一真相（手写）
├─ fonts/                          字库（与资产框架无关，独立）
├─ monsters/                       怪兽本体
│  └─ godzilla/
│     ├─ rig.json                  运行空间骨骼数据（生成）
│     ├─ rig.data.js               同上，浏览器可加载（生成）
│     ├─ parts/<槽位>/<样式>.png    12 个骨骼槽
│     └─ source/
│        ├─ godzilla-pixel.png     母图
│        └─ parts.json             母图空间裁切元数据（手写）
├─ enemies/                        敌对单位
│  └─ <阵营>/<单位>/
└─ buildings/                      建筑
   └─ <幕>/<建筑种类>/
```

### 2.2 怪兽：`monsters/<怪兽>/`

- 一级目录 = **怪兽**（`godzilla`）。加新怪兽就在这一层加同级目录。
- 二级固定三项：`parts/`（部件贴图）、`source/`（母图与裁切元数据）、
  两个生成文件 `rig.json` + `rig.data.js`。
- `parts/` 三级 = **槽位名**，必须恰好是这 12 个（见框架文档 §2.3），
  多一个少一个都是错误：

```
head  jaw  torso  upper_arm  forearm  thigh  shin
far_thigh  far_shin  tail_base  tail_mid  tail_tip
```

- `parts/<槽位>/` 四级 = **样式文件**。默认样式必须叫 `default.png`；其他样式
  与 `default.png` 同级并列。

### 2.3 敌人：`enemies/<阵营>/<单位>/`

- `<阵营>`：当前只有 `army`（防卫军），登记在 `asset-index.js` 的 `ENEMY_FACTIONS`。
- `<单位>`：单位 id，必须是 `ENEMY_UNITS` 的键，逐字符相同：

```
enemies/army/
  tank  heli  rocket  gunship  aegis
  mech  jet   drone   walker   bunker
```

- 单位目录内部与怪兽同构：`parts/<部件>/<样式>.png`。
  部件名（如坦克的 `track` / `hull` / `turret` / `barrel`）在
  `ENEMY_UNITS[].slots` 里声明。
- `parts/` 子目录在**第一个贴图落地时**才创建，不预建空目录。

### 2.4 建筑：`buildings/<幕>/<建筑种类>/`

- `<幕>` 与 `progression.js` 的 `STAGES[].key` 一致：`village` / `suburb` / `city`。
- `<建筑种类>` 在 `BUILDING_KINDS[<幕>].kinds` 里声明：

| 幕 | 建筑种类 |
| --- | --- |
| `village` | `house`、`shop` |
| `suburb` | `house`、`shop`、`midrise` |
| `city` | `tower`、`block` |

- 同一幕里多个建筑种类共用的部件，放 `buildings/<幕>/_shared/<部件>/<样式>.png`。

## 3. 命名规范

| 对象 | 规则 | 例 |
| --- | --- | --- |
| 怪兽 id / 阵营 id / 单位 id / 幕 id | 小写 ASCII + 下划线 | `godzilla`、`army`、`far_thigh`、`suburb` |
| 槽位 / 部件名 | 同上，与代码里的 id 逐字符相同 | `upper_arm`、`tail_mid` |
| 样式名 | 小写 ASCII + 下划线；默认样式**必须**是 `default` | `default`、`crystal`、`hammer` |
| 贴图文件 | `<样式>.png`（小写扩展名） | `default.png` |
| 母图 | `<怪兽>-pixel.png` | `godzilla-pixel.png` |
| 手写数据 | `<用途>.json` | `parts.json` |
| 生成文件 | `<用途>.json` + `<用途>.data.js` 成对 | `rig.json` / `rig.data.js` |

- **目录名只允许**小写字母、数字、下划线（`^[a-z0-9_]+$`），不允许 `.` 与 `-`。
- **文件名额外允许** `.` 与 `-` 作分隔符，且只用于上面两类固定写法
  （`rig.data.js`、`godzilla-pixel.png`）；分隔符不得出现在首尾或连续出现。

禁止：中文文件名、空格、大写字母、版本号后缀（`v2`、`final`、`new`、`副本`）。
**不要用文件名管版本** —— 版本由 git 管。

## 4. 贴图规格（硬约束）

### 4.1 尺寸

1. **同一槽位的所有样式必须与 `default.png` 像素尺寸完全相同。**
   枢轴偏移存的是母图空间整数（`rig.json` 的 `pivotOffset`），
   尺寸一变，挂点就错位。
2. **不要用改图幅的方式实现"某个部件变大/变小"。** 那是「大小」轴的事：
   在 `appearance.js` 的 `FORMS[i].size` 里写倍率，挂点会自动跟随。
3. 若确实需要不同轮廓（新造型而不是缩放），走母图流程重新拆件（§5），
   当作新形态处理，而不是塞进同一个槽位的样式目录。

### 4.2 像素格式

- PNG-32（带 alpha），透明背景。
- 硬边，**不要抗锯齿、不要半透明边缘渐变、不要缩放重采样**。
  本项目验收基线之一是"12 部件重组后与原图 RGB 差 0"，
  抗锯齿边缘会让这个比较失效。
- 不要给贴图加投影、外发光、描边 —— 辉光由装饰槽程序化绘制，两者会叠加。
- 不要在贴图里烘焙体色。体色走「颜色」轴。

### 4.3 母图流程（重新拆件时）

母图 `source/godzilla-pixel.png` 是**唯一来源**，`source/parts.json`
记的是母图空间的裁切框与原始枢轴。改母图后必须重跑：

```bash
node build/derive-rig.cjs          # 重算并写入 rig.json + rig.data.js
node build/derive-rig.cjs --check  # 只校验，不写盘
```

推导脚本会做三件事，任一不通过就报错退出：

1. 12 个槽位的部件图必须存在，且**实际像素尺寸**与 `parts.json` 声明一致；
2. 按 `枢轴偏移 × 比例` 重算枢轴，并与 `approvedPivot`（视觉验收时的枢轴像素值）
   对账，偏差 > 0.01 px 即失败；
3. 12 个槽位的比例必须完全相同（全局装配比例只有一个）。

`parts.json` 里**不允许出现运行期路径**（如 `src`、`assets/...`）。
母图空间的东西只描述母图空间。

## 5. 三个轴的合法取值

### 5.1 样式 style

- 取值必须是在 `asset-index.js` 的 `MONSTERS.<怪兽>.styles` 里**登记过**的名字。
- 未登记就引用 → 测试失败（`Appearance.validate()`）。
- 缺图时该部件不绘制（沿用既有行为），但**测试会拦下缺图**，不会让它上线。

### 5.2 颜色 color

| 取值 | 载体 | 当前生效范围 |
| --- | --- | --- |
| `none` | 原色 | — |
| `crimson` | 叠色 `#ff3b2e` α 0.18 | 装饰槽 |
| `albino` | 叠色 `#eaf6ff` α 0.14 | 装饰槽 |
| `obsidian` | 叠色 `#0a0a12` α 0.22 | 装饰槽 |
| `jade` | 叠色 `#2fae6a` α 0.16 | 装饰槽 |

调色板定义在 `appearance.js` 的 `PALETTES`。加新体色 = 在这里加一格 +
在 `progression.js` 的 `MUTATIONS` 里加 `cat:'trait'` 突变。

**注意**：调色板对 12 个骨骼槽目前**只记录、不施加**（原因见框架文档 §5）。
不要在资产里"预先染色"来模拟这个效果 —— 那会让同一张图无法被多个体色复用。

### 5.3 大小 size

- 合法区间：`0.85 ~ 1.25`。超出会被 `Appearance.clampSize()` 夹回来。
- 单槽位大小是**相对基准的倍率**，不是绝对尺寸。
- 超过 `1.25` 说明这已经不是同一套骨骼能承受的形变 ——
  **应该新开一档形态**，而不是继续拉大某个槽位。
- 想让整只怪兽变大，改 `growth.js` 的体型曲线（1 级 0.34 → 满级 1.00，`CEIL` 上限 1.12），
  不要叠到单槽位上。屏幕上的最终大小还要乘镜头（`growth.cameraScale()`）——
  改体型前先读 `tv/DESIGN.md` 的「屏幕表观尺寸 = 体型 × 镜头」。
  （旧文这里写的"体型档 1.00~1.80"是废弃的第二套公式，已不存在。）

## 6. 手写物 / 生成物边界

**不许手改**（文件头会写明来源）：

| 文件 | 由谁生成 |
| --- | --- |
| `monsters/<怪兽>/rig.json` | `build/derive-rig.cjs` |
| `monsters/<怪兽>/rig.data.js` | `build/derive-rig.cjs` |

**手写**（改了要跑校验）：

| 文件 | 内容 |
| --- | --- |
| `monsters/<怪兽>/source/parts.json` | 母图裁切框、原始枢轴、`approvedPivot` 回归锚点 |
| `tv/assets/asset-index.js` | 路径与清单 |
| `tv/appearance.js` | 形态与三轴 |
| `tv/rig.js` 的 `SEAMS` | 关节内侧补片（母图空间矩形） |

## 8. 反例清单（不要做）

| 反例 | 为什么不行 | 正确做法 |
| --- | --- | --- |
| 在 `rig.js` 里加一行 `PARTS.head.src = '...'` | 路径的唯一真相在 `asset-index.js` | 改 `asset-index.js` 或 `parts/<槽位>/` 下的文件名 |
| 手改 `rig.json` 的枢轴 | 下次跑推导脚本会被覆盖，且与验收基线脱钩 | 改 `parts.json` 后重跑 `derive-rig.cjs` |
| 把部件图放大 1.2 倍另存为新样式 | 枢轴偏移会失配，部件从关节上掉下来 | 用 `FORMS[i].size = 1.2` |
| 把 `head` 改名成 `Head` 或 `头部` | 骨骼契约、目录名、索引三方对不上 | 保持 `head`；显示名放 `label` 字段 |
| 加一个 `hand` 槽位 | 手与爪的像素在 `forearm.png` 里，没有对应骨骼 | 先改母图拆件，再考虑加槽位 |
| 在 `game.js` 里写 `if (morph.xxx)` 加新体征 | 分支链会重新长回来，这正是框架要消掉的 | 在 `appearance.decor()` 里加一格 |
| 给贴图加抗锯齿边缘 | 破坏"重组与原图差 0"的验收基线 | 保持硬边像素 |
| 同一个"变大"既改图幅又写 size | 双重缩放，且挂点失配 | 只走 size 轴 |
