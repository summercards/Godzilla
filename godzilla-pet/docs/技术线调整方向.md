## 0. 定调推导出的三条第一性约束

| 约束 | 含义 | 它否掉了什么 |
|---|---|---|
| **窗口层是产品本体，不是障碍** | 无边框 / 不占任务栏 / 置顶 / 无 Dock 图标全部是卖点 | 否掉「改成常规游戏窗来解决 Steam 问题」这条逃逸路线 |
| **7×24 常驻是第一性** | 用户从不主动关闭，可能连跑几天 | 否掉「短会话」假设下的存档、退出、日志设计 |
| **面板窗才是"游戏 UI 的正规位置"** | 电视窗纯观赏，交互全在副屏 | 否掉「把交互塞回小电视」的所有方案 |

**核心判断：形态定了之后，「窗口层」不需要改，需要改的是它下面那三层（存档 / 退出 / 可观测性），以及那条一直别扭的 `tv/` 只读边界。**

## 1. 已定决策（2026-09-17 确认）

| # | 决策 | 结论 | 理由摘要 |
|---|---|---|---|
| **D1** | Overlay 要还是不要 | **不要** | 桌宠是最不需要 Overlay 的品类（常驻桌面，旁边就能开 Steam 客户端）。SDK 照接（成就/云存档与 Overlay 无关）；成就弹窗自做（可做成 GNN 风格，`banner()` 已在）；截图用 `capturePage()`，还能带上电视边框和 HUD。避开 `setAlwaysOnTop('screen-saver')` + `setVisibleOnAllWorkspaces` 与 Overlay 的结构性冲突 |
| **D2** | 面板尺寸解耦 / 允许缩放 | **解耦做，自由 resize 不做** | 改为「面板大小」三档枚举。理由：面板是 `frame:false`，macOS 上无边框窗**没有系统 resize 抓取区**，自由拖动会拖不动 |
| **D3** | `contextIsolation` 的债 | **排期，但不抢先** | 现在**没有安全问题**（`nodeIntegration:false` 挡住 `require`，页面只加载本地文件、无远程内容、无外部导航）→ 是技术债不是漏洞。真正收益是**可升级性**（Electron 持续收紧隔离），真正风险在**存档** → 必须搭已有存档回归覆盖一起做 |

**D1 的落地后果**：Step 1-6 里**不存在**任何 Steamworks / Overlay 相关工作。SDK 接入属发行期，不在本计划内。

### Step 4｜面板尺寸解耦（三档枚举）

**目标**：面板尺寸脱离电视档位。让玩家能做「小电视 + 大面板」——**电视是摆件，面板是操作台**。

**现状**：`main.js:312` 面板尺寸硬跟电视档位走

```js
const s = curSize();
height: Math.round(s.h * PANEL_H_SCALE)   // PANEL_H_SCALE = 1.45（main.js:66）
```

→ small 档面板只有 **448×426**，而 `PANEL_READABLE_CSS` 把资源数字吹到 **20px**、内容又是「4 列资源条 + 3 个页签 + 卡片网格」→ 必然挤压换行。

**改动**
1. `tv-config.js` 新增 `PANEL_SIZES` 三档（建议基准：`compact 560×640` / `standard 640×760` / `tall 720×900`，**具体数值按 Step 4 实机截图微调**）

3. `main.js:308` / `:312` 不再用 `curSize()`；删除 `main.js:66` 的 `PANEL_H_SCALE`（它存在的唯一理由就是"跟电视走"）
4. 面板尺寸变为**独立持久化状态** → 加进 `pet-window.json` 的 `state`（`main.js:119-125` 已有三种历史形状的兼容先例，**新字段必须给默认值，旧档不能崩**）
5. 面板「设置」里加「面板大小」三档选择
6. **明确不做** `resizable: true`（决策 D2）

**验收**

**目标**：还掉那笔债，让 Electron 能持续升级。

**⚠️ 范围勘误（本文件 v1 曾写错）**：**不是"动 `tv/game.js` 两处"**。真实耦合是一个**双向的 window 全局契约，至少 6 处**：
