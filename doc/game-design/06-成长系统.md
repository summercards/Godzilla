## 1. 总览：三种货币，三种东西

现有系统只有一种成长货币（`dna` 突变点）和一种数值货币（核能）。这个设计加上第三种。

| 层 | 货币 | 来源 | 花在 | 它决定什么 |
| --- | --- | --- | --- | --- |
| **强化**（现有） | 核能 | 挂机产出 | 四项强化：力量 / 炉心 / 代谢 / 动能 | 数值的底子 |
| **技能树**（现有） | `dna` 突变点 | 升级 +1、突破区域 +2 | 3 分支 × 3 节点 | 它能**做什么** |
| **天赋网格**（新增） | `talent` 天赋点 | 每 3 级 +1、Boss 首杀 +1 | 3 环 × 6 节点 × 3 级 | 它**是什么** |
| **随机突变**（新增） | 不需要货币 | **每级自动抽 1 次** | — | 它**长什么样** |

关键分工：**技能树管行为，天赋管体貌，随机突变管惊喜。**
三者不互相替代，也不抢同一个货币。

### 成长主线

```
      经验 ──► 等级 ──┬──► +1 天赋点（每 3 级）──► 天赋网格（可选、可规划）
                     │
                     ├──► +1 dna（现有）────────► 技能树（可选、可规划）
                     │
                     └──► **1 次随机突变**（自动、不可规划）
                                  │
                                  ├──► 属性数值（免费加点）
                                  ├──► 身体部位异变（外观）
                                  └──► 体型 / 元素 / 体色改变
                                              │
                                              ▼
                                    屏幕上那个东西长得不一样了
```

## 2. 等级系统

### 2.1 沿用（不改）

```
M(level)  = 1 + (level-1) × 0.07
nextXP    = round(260 × level^1.28)
升级获得   = +1 dna（现有）
```

### 2.2 新增：经验收益的区域缩放

**这是前置修复，不是可选项。** 完整推导见 [`01-设计总纲.md`](01-设计总纲.md) §6，结论：

```
击破敌人经验 = round(12 × Ke(d))          Ke(d) = 1 + (d-1) × 0.19
摧毁建筑经验 = round((layer===1?24:12) × Kb(d))   Kb(d) = 1 + (d-1) × 0.22
突破区域经验 = round(60 × Ke(d))
```

修正后稳定在**每 3 个区域升一级**，与"一章 5 关"的节拍正好契合。

### 2.3 新增：体征期（Epoch）

每 25 级一个质变台阶。**不单独存储，由 `level` 推导。**

| 体征期 | 等级 | 体型系数区间 | 名称 | 外观质变 |
| --- | --- | --- | --- | --- |
| I | 1–24 | 1.00 – 1.15 | **幼兽** | 原始墨绿，3 根矮背刺，无元素 |
| II | 25–49 | 1.16 – 1.32 | **亚成体** | 背刺分叉，鳞甲出现分块，体型明显超过大多数建筑 |
| III | 50–74 | 1.33 – 1.49 | **成体** | 主元素定型（背刺开始带色），尾巴分出更多节 |
| IV | 75–99 | 1.50 – 1.65 | **完全体** | 背刺完全元素化，体色发生可见偏移，体表出现纹路 |
| V | 100+ | 1.66 – 1.80 | **灾厄体** | 体表元素辉光，每步落地产生余波，阴影变形 |

**体征期转换是可看的仪式**：全身被粒子包裹重构 2.5 秒（慢动作 1.0 秒），
新闻特别报道一次，体型在那个瞬间跃升一个台阶。

## 3. 天赋网格（Talent Grid）

### 3.1 规则

| 项 | 值 |
| --- | --- |
| 节点数 | 18（3 环 × 6） |
| 每节点等级 | 1–3 |
| 天赋点来源 | 每 3 级 +1；**每关 Boss 首杀 +1**；静默天气下升级额外 +1（稀有） |
| 重置 | 免费重置一次，之后每次消耗 `2000 × 1.8^次数` 核能 |

## 4. 随机突变系统（本设计的核心）

### 4.1 规则

| 项 | 值 |
| --- | --- |
| 触发 | **每升一级获得 1 次「进化机会」**（`evoRolls +1`），机会可累积、不封顶 |
| 额外次数 | Lv 25 / 50 / 75 / 100（体征期转换）**额外 +1 次机会** |
| 怎么用掉 | **自动进化开启时**（默认）自动掷，只在电视窗口播 0.8 s 快闪角标；**关闭后**由玩家在面板「进化」菜单里点「掷骰进化」 |
| 是否需要货币 | **不需要** —— 它是升级的赠品，不是消费 |
| 可否重掷 | 可以：消耗 `5000 × 1.6^重掷次数` 核能，随机替换最近一次突变 |
| 是否可逆 | 不可逆。这是"这头巨兽独一无二"的来源 |
| 是否落盘 | **落盘**（`mutations` 数组），同时用 `seed` 双保险 |

> **骰子只是仪式，不是随机源。** 点击「掷骰进化」时，结果**已经由
> `seed + level` 算完了**；动画只是落在那个已知的面上。
> 界面、动画时间轴、骰面与稀有度的映射，全部在
> [`07-成长界面与表现.md`](07-成长界面与表现.md) §6。

## 5. 体型成长

### 5.1 公式

```
globalScale = clamp( 1
    + 0.005 × (level - 1)          // 等级：Lv100 时 +49.5%
    + 0.02  × mass天赋等级          // 0 – 6%
    + 0.03  × magma天赋等级         // 0 – 9%
    + 0.03  × epochIndex            // 体征期台阶 0 – 12%
    + 0.015 × 巨躯化类突变数量       // 每个 +1.5%
  , 1.00, 1.80 )
```

### 5.2 分部位倍率

全身缩放之外，各部位可以有自己的额外倍率（由部位突变叠加）：

| 部位组 | 额外倍率上限 | 说明 |
| --- | --- | --- |
| 躯干 `torso` | ×1.18 | 最影响整体剪影 |
| 背刺 `spikes` | ×1.60 | 长得最夸张的地方，视觉主角 |
| 尾巴 `tail_*` | ×1.25（长度方向） | 长度可独立拉长 |
| 前肢 `upper_arm` / `forearm` | ×1.15 | |
| 后肢 `thigh` / `shin` | ×1.12 | |
| 头部 `head` / `jaw` | ×1.10 | 头不能太大，否则破坏比例观感 |

### 5.3 三条工程约束（不遵守会直接坏）

| 约束 | 说明 |
| --- | --- |
| **缩放锚点是脚底，不是中心** | 现有 `rig.js` 以 `torso` 的 `sourcePivot` 为原点。体型缩放必须让**脚不离地**（脚底贴 `G`），否则巨兽会浮空或陷地 |
| **判定范围必须同步放大** | 爪击判定 135px、建筑接触 70px、重踏/尾扫范围，全部乘以 `globalScale`。**"变大了却打不到"是体验硬伤**，比不变大更糟 |
| **上限 1.80 是硬约束** | 巨兽变大后头顶不能越过页眉下沿、不能遮住底部新闻条。1.80 是初值，实现时按实际像素标注校准 —— 这条必须在实测里确认，不能拍脑袋 |

> 相机、地面线 `G`、建筑比例**一律不动**。只缩放巨兽自身的绘制变换。
> 这样"巨兽相对建筑变大"的观感才会成立（改相机会把整个构图改掉）。

### 5.4 外观可以推演，但必须落盘

理论上面貌完全可以从 `mutations` + `talents` + `level` 推演出来。
**但仍然要把结果落盘**（`morph` 快照），理由是：

- 推演逻辑将来一定会改（加新突变、调公式），一改旧档的外观就会漂移
- 外观漂移 = 玩家的巨兽一夜之间变了样 = 比丢档更难受的体验

**双保险：`seed` 保证随机序列可复现，`mutations` 保证已发生的事不会变。**

## 6. 确定性随机（铁律 5 的落地）

**绝对不能用 `Math.random()` 决定任何外观。**

```js
// 与天气系统共用同一份实现（放在 progression.js 中导出）
function hashSeed(seed, level) {
  let h = 2166136261 ^ (seed | 0);
  h = Math.imul(h ^ (level | 0), 16777619);
  return h >>> 0;
}

function mulberry32(a) {
  return function () {
    a = (a + 0x6D2B79F5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

function mutateFor(seed, level, weather, talents) {
  const rng = mulberry32(hashSeed(seed, level));   // 每一级一个独立的确定性序列
  const rarity = rollRarity(rng, weather);         // 天气修正稀有度权重
  const pool   = pickCategory(rng, weather);       // 天气加权类别
  return pickFromPool(rng, pool, rarity, weather);
}
```

**同一个 `seed` + 同一个 `level` 永远抽出同一个突变。**
精英单位的词缀抽取（见 [`03-敌人图鉴.md`](03-敌人图鉴.md) §4）也用同一套函数。

> 注意这里**不使用全局的连续 RNG 流**，而是「按 level 派生独立序列」。
> 原因是：如果将来在别处插入一次随机调用，连续流会导致后续所有突变错位，
> 已落盘的 `mutations` 与新抽出的就对不上了。按 level 派生则天然隔离。

## 7. 存档扩展

### 7.1 新增字段

```
version    3 → 4        ⚠️ 见 7.3 的风险提示
talent     number       天赋点余额（新档 0）
talents    {id: level}  天赋等级表（新档 {}）
assign     number       可用加点机会，每级 +1（新档 0）
evoRolls   number       可用进化机会，每级 +1（新档 0）
mutations  [string]     已获得突变 id，按获得顺序（新档 []）
seed       number       突变种子（新档生成一次后永久固定）
rerolls    number       已用重掷次数，用于定价（新档 0）
```

### 7.2 不新增的字段

| 数据 | 为什么不存 |
| --- | --- |
| 天气 | 由 `seed + district` 确定性派生（[`05-天气系统.md`](05-天气系统.md) §2） |
| 体征期 `epoch` | 由 `level` 直接推导 |
| 体型 / 元素色 | 可由 `mutations + talents + level` 推导；但**仍然存 `morph` 快照**（见 §5.4），快照挂在 `mutations` 的推导结果上，不额外增加字段 |

### 7.3 ⚠️ 升版本的真实风险

`progression.js` 的 `sanitize()` 现在是这么开头的：

```js
function sanitize(raw) {
  let a = defaults();
  if (!raw || raw.version !== 3) return a;    // ← 旧版本直接当新档
  ...
}
```

**只把 `version` 改成 4，等于把所有人的存档判废、回落到 1 级。**
必须同时改判定，并且就地补齐新字段：

```js
if (!raw || (raw.version !== 3 && raw.version !== 4)) return a;
// version === 3 时：保留全部已有字段，只补 talent/talents/mutations/seed/rerolls
```

`seed` 的迁移派生也必须是确定性的 —— **不能用 `Date.now()` 或 `Math.random()`**：

```js
// 迁移时从旧档已有且当时稳定的字段派生一次
data.seed = hashSeed(raw.cleared * 7919 + raw.kills * 104729 + Math.round(raw.meters), raw.level);
// 派生后立即落盘，之后永远从存档读，不再重算
```

即使派生后立刻崩溃、下次重新派生得到不同的 `seed`，代价也只是**再抽一次**
（因为 `mutations` 已经落盘，已获得的外观不会变）。这是有意的降级设计。

### 7.4 桌宠侧

**`godzilla-pet/` 下的文件一行都不用改。**

存档接管层只做字符串透传，不解析 `payload`，所以 `version 3 → 4`
对桌宠完全透明。但必须回归验证这两条现成断言：

- `save-store.test.cjs` —— `payload` 逐字往返（连续写入 50 次不漂移）
- `tv.test.cjs` —— 劫持的键必须与画面里的 `SAVE` 常量一致、画面必须仍是同步读档

### 关于背刺的绘制方案

背刺目前**烘焙在 `torso.png` 里**（不是独立部件），所以"背刺数量与高度可变化"
需要一个新增绘制层：

- **方案（推荐）**：在 `torso` 之上叠一层程序化绘制的背刺（像素方柱 + 渐变），
  位置从躯干骨骼变换推导。原背刺是深色剪影，被同色系的新层覆盖不会突兀。
- **代价**：极低等级（背刺少）时可能与原图有 1–2 像素的观感差异。
  可以考虑"等级 < 10 时不绘制新层"，把那时的画面完全让给原图。
- **不做的事**：重新切割 `torso.png`。那会破坏 `ART-DIRECTION.md` 里
  "静止重组与原图像素差异为 0"这条已实现的成果。
