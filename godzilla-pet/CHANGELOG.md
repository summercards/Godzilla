# 2.6.2（未打包）· 启动那几秒看得见了

> 状态：**源码已生效，尚未打包**。`package.json` 与 `build/make-app.sh` 仍是
> `2.6.1 / 27`，本次改动随下一次打包带上；打包前把这两处升到 `2.6.2 / 28`。
> 主人跑的是源码版，重启即生效。

修：双击 `start-godzilla.bat` 之后，要再点一次游戏才出来。

结论是：**不是需要点两次，是第一次点击之后那几秒里，屏幕上一个能认出来的东西都没有。**

## 两次点击各自做了什么

| 第几次 | 实际动作 | 日志里看得到吗 |
| --- | --- | --- |
| 第 1 次 | 启动、拿单实例锁、建窗口。窗口是 `transparent` + 全透明底色，而抹掉页面底色的 `TV_TRANSPARENT_CSS` 要等 `did-finish-load` 才注入 —— 在那之前桌面上**没有任何轮廓** | 看得到 |
| 第 2 次 | 拿不到锁 → `app.quit()`。这句在 `app.whenReady()` **之前**，`initObservability()` 根本没跑 | **看不到，一行都不留** |

所以「第 2 次」在日志里查不到，这本身就是判据：`main.log` 里「电视窗口已创建」
前面没有「启动」行 = 同进程重建窗口（second-instance 或托盘左键），不是新进程启动。

## 改动

| 文件 | 改了什么 |
| --- | --- |
| `tv-config.js` | 新增 `TV_STARTUP_CSS`：`html, body { background:#050a15 !important }` |
| `main.js` | `dom-ready` 注入 `TV_STARTUP_CSS`，`did-finish-load` 再由 `TV_TRANSPARENT_CSS` 覆盖回透明 |
| `main.js` | `second-instance` 补显式 `show()` + `focus()`——原来的 `toggleVisible(false)` 对已显示的窗口是空操作，点完毫无反馈 |
| `main.js` | `createWindow` 拆成「闸门 + `buildWindow`」，堵掉两个入口撞车时重复建窗 |
| `main.js` | 「电视窗口已创建」加 `id` / `pid`；新增两条启动耗时日志（`sinceCreateMs`） |

**注入顺序不能调换。** 两条选择器与 `!important` 完全相同，层叠规则在同优先级下判
「后插入者胜」—— 反过来就是一块永远不透明的深色矩形，透明效果整个失效。

## 边界

- 只碰 `html, body` 的 `background`，**没有动 `tv/` 里任何一个文件**。
- `TV_STARTUP_CSS` 只注入电视窗口；面板本来就不透明，不注入。
- 启动底只活到 `did-finish-load`，画面出来之后与改动前一个像素都不差。

## 验证

- 隔离 userData 起 6 次，`sinceCreateMs`（createWindow → dom-ready）稳定在 683~2074 ms，
  `窗口已可见（启动底已刷）` 与 `画面已加载（启动底已交还给透明）` 成对出现。
- 脚本模拟「1.4 s 后再点一次」连跑 4 次：第 2 个进程每次 `poll=0` 干净退出、零日志，
  「电视窗口已创建」始终 1 条。**同一实验还量到"再点一次会让等待更长"**：无人打扰时
  该指标约 2.0 s，第二个进程在旁边启动时涨到 17.0 s。
- 回归 127 项：119 通过、0 失败、8 项 macOS 跳过。

## 那条"删掉 GPU 参数"的路子走不通

`--in-process-gpu --disable-gpu --no-sandbox` 看着像沙箱适配的遗留，删过一次，**删了就崩**：

| 参数 | 结果 |
| --- | --- |
| 带 | 窗口出现、页面加载、正常运行 |
| 不带 | 进程在「电视窗口已创建」之后**立刻死**，退出码 `0x80000003`，页面从未加载 |

同一份构建、同一份隔离 userData，唯一变量是这三条。它们也**不是**启动慢的原因
（不带沙箱实测「窗口创建 → 页面就绪」只要 **441 ms**）。启动慢另有原因，存档大小已排除
（有档 2063 ms / 空档 2074 ms），剩下的指向当时的机器负载。详见 `README.md`
「踩过的三个坑」第三节。

# 2.6.1 · 电视柜以外透出桌面

修：小电视四周那一圈深色留白。用户报的现象是「窗口周边还有黑边，电视背面不是
透明的吗」。答案是：**它从来没透明过** —— 那圈留白是两层底色叠出来的。

## 两层，少改一层都还是黑的

| 层 | 位置 | 改动 |
| --- | --- | --- |
| 窗口层 | `main.js` 电视窗口 | `transparent: false` → `true`；底色 `#050a15` → `#00000000` |
| 页面层 | 新增 `TV_TRANSPARENT_CSS` | `html, body { background: transparent !important }` |

只改窗口层没用：页面自己给 `html/body` 各刷了一层 `#050a15`，还叠了径向渐变，
照样铺满整个视口。只改页面层也没用：窗口底板还在。两层都动，柜外才是桌面。

## 那圈留白有多厚，是版面算出来的

视口 1120×736，`.shell` 只有 1088×625 且垂直居中：

| 方向 | 视口里 | small 档（×0.4）实到屏幕 |
| --- | --- | --- |
| 左右 | 各 16px | 各 6.4px |
| 上下 | 各 55px | **各 22px** |

上下比左右厚三倍多 —— 这正是用户截图里"上下黑边明显更宽"的来源。

## 边界

- **面板窗口不跟着透明**：它是一块摆在电视旁边的菜单，字压在壁纸上只会更难读。
  它的 `backgroundColor` 仍是 `#050a15`，也不注入 `TV_TRANSPARENT_CSS`。
- **只碰 `html, body`**，不碰 `.tv-cabinet` / `#playerFrame`。碰了就成了改画面定义，
  不是改窗口。选择器白名单有断言。
- `TV_DRAG_CSS` 与 `TV_TRANSPARENT_CSS` 是**两条独立常量**：拖动那条一个字都不许
  带视觉属性（既有断言），所以透明度必须另开一条。

## 验证

- 契约测试新增 1 条（`tests/tv.test.cjs`，31 项）：各钉一层 + 注入范围。
- **变异测试**：把 `transparent` 改回 `false`、把底色改回 `#050a15`、删掉那句
  `insertCSS(TV_TRANSPARENT_CSS)` —— 三种改法各自都能让这条断言变红。
- **实测（Windows 11，2560×1440，scale 1.0）**：
  - 页面层：`html`/`body` 的 computed background 都是 `rgba(0,0,0,0)`；
  - 窗口层：铺一块纯洋红全屏底，留白处像素就是洋红；上留白 100% 透出；
  - **最硬的一条**：留白处的桌面像素与"窗口关掉后"的同一像素**逐字节相同**；
  - 端到端回归：开面板、切 tab（不带开电视的面板）、操作转发、面板仍不透明，全照旧。

## 已知代价

- 柜外那圈"空气"看不见但**仍属于窗口**，鼠标移上去会被窗口接住，点不到底下的
  桌面图标。要改需 `setIgnoreMouseEvents` + 逐区域动态开关，本版不做。
- 柜子周围剩的那圈**深浅渐变**（贴圆角轮廓、越往外越淡）是 `tv/style.css` 里电视柜
  自己的 `box-shadow`，属画面的一部分，不是窗口底色。
- 副屏壁纸是近黑（`#141414`，亮度 20），旧底色 `#050a15` 亮度 12 —— **在暗色壁纸上
  这次改动肉眼不明显**，要看效果请把电视拖到亮色区域。已记入
  `docs/平台验证清单.md` 第 9 项（透明窗在 Windows 上的表现，含 macOS
  `invalidateShadow()` 残影风险，未实测）。

# 2.6.0 · 成长系统：加点 / 天赋 / 随机突变

按 `doc/game-design/06-成长系统.md` 与 `07-成长界面与表现.md` 落地，替换原来的
「数值强化」面板。原来那套（核能买强化 + dna 技能树）保留，作为四层里的两层。

## 四层成长

| 层 | 货币 | 来源 | 决定什么 |
| --- | --- | --- | --- |
| 强化（原有） | 核能 | 挂机产出 | 数值的底子 |
| **加点（新增）** | 加点机会 | 每级 +1、突破区域 +1 | 保底成长，不看核能 |
| 技能树（原有） | dna | 升级 +1、突破区域 +2 | 它能做什么 |
| **天赋（新增）** | 天赋点 | 每 3 级 +1 | 它是什么（体貌） |
| **随机突变（新增）** | 不需要货币 | 每级自动抽 1 次 | 它长什么样 |

## 数值层（tv/progression.js）

- 存档 `version 3 → 4`：新增 `talent` / `talents` / `assign` / `evoRolls` /
  `mutations` / `seed` / `rerolls` / `talentResets` / `morph` / `subElements`。
  **判定写成「3 和 4 都认」**，旧档照读、就地补齐新字段 —— 只把版本号改成 4
  会把所有人的档判废回落到 1 级。
- `seed` 迁移用 `hashSeed(cleared·7919 + kills·104729 + meters, level)` 从旧档
  已有字段确定性派生，绝不用 `Date.now()` / `Math.random()`。
- 18 个天赋节点（3 环 × 6 × 3 级），三环门槛（上一环累计投入 ≥4 开启下一环）；
  第一个点满 3 级的元素节点成为主元素（决定背刺与吐息颜色）。
- 28 条突变（属性 / 部位 / 元素 / 质变四类），稀有度权重 60/25/11/3.5/0.5。
  抽取用 `hashSeed + mulberry32`，**按 level 派生独立序列**（不用全局连续流，
  否则将来在别处插一次随机调用，后续突变全错位）。
- `globalScale` 体型缩放，锚点脚底、上限 1.80 硬约束。
- 经验收益区域缩放 `Ke/Kb`，修正到「每 3 个区域升一级」的节拍。

  面板里 `TV_HIDE_DOCK_CSS` 也注入了，所以面板里只留 `.tabs` 一套导航。
- **面板窗口尺寸跟电视窗口档位走**（不放大到 1:1）—— 用户反馈面板比电视大很多
  很突兀，改成一个尺寸、成套摆放。位置贴在电视窗口外侧（右侧优先，顶边翻左侧，

  用户点按钮看到的还是老面板，新系统藏在 tab 里根本没人知道。

## 桌宠侧（main.js + panel-preload.js）

- `panel:tap` 接出 `executeJavaScript` 的返回值，若是对象就回推 `panel:rolled`
  给面板播骰子动画（动画不参与计算，落在电视窗口算好的面上）。
- 新增 `panel:sync`：电视窗口每次落盘后把 payload 推给面板 —— 没有这条，
  面板的角标永远不亮（面板只读，电视在跑、面板不知道）。
- `panel-preload.js` 的点击转发收紧成**只转发、不本地执行**，且白名单只收
  「会改游戏状态」的控件。避免一次点击双写（面板本地改内存、电视又改真实状态）。

## 面板窗口的四轮修正（用户实测反馈）

第一轮反馈：「点开还是老面板，而且很大」→ 默认页改落「加点」、尺寸跟电视档位成套。
第二轮反馈：「面板里很多别的信息、字太小」「有些功能窗口跑到电视机里了」。
第三轮反馈：「按钮还是太小了，字也太小了，文字要匹配大一些」。

- **功能窗口跑进电视机** —— 转发白名单 `/^(assign|talent|...)[-\w]*$/` 连
  `talentTab` / `assignTab` / `skillsTab` / `evoTab` 一起匹配了（它们都带操作
  前缀）。面板里切个页，电视窗口就执行同一个 id，把自己的观测面板弹开，
  直播画面被功能页整个盖住。修复：Tab 结尾 / `closePanel` / `evoSpeed`
  一律本地执行；`fullscreen` / `dismiss` 从白名单剔除（转发 fullscreen 会去
  全屏电视机窗口）。这条单独钉了契约测试。
- **面板里全是直播包装、字看不清** —— 面板加载的是完整直播页（台标、机位、
  滚动新闻条全在），又继承了电视的 0.41 缩放，12px 的字落到屏幕上只剩 5px。
  两步修：
  - 新增 `PANEL_ONLY_CSS`（只在面板窗口注入）：直播包装全部藏掉、
    `#stage` 解除 16:9 让观测面板铺满窗口、`.obs-title` 顶上来当拖动把手；
  - **zoom 显式钉回 1**。这条最阴：面板分支根本没有设缩放的代码，
    但 Chromium 把缩放按**来源**存在会话里 —— 电视窗口对同一个 `file://`
    页面设过 0.41，面板加载同一来源时静默继承。不显式 `setZoomFactor(1)`，
    "面板不缩放"就只是个没生效的愿望。
  - zoom=1 之后，游戏自己的窄屏紧凑断点（`max-width:680` 与
    `max-height:480 横屏`）原生命中面板窗口的形状：header/footer 自动隐藏、
    双列网格、字号回到真实的屏幕像素。
- **加点面板布局错误** —— `#assignPanel` 误用了 `upgrade-grid`（那是给四张
  并列卡片用的网格），「标题行」和「卡片区」被当成网格里的两个格子并排挤压，
  窄窗里卡片被裁切、出现横向滚动条。改成 `assign-panel` 上下排布，卡片轨道
  用 `minmax(0,1fr)` 允许收缩（grid 子项的 `min-width:auto` 会用内容宽度
  撑破容器）。

### 第四轮：颗粒与字号

- **窗口外的控制按钮 64px → 88px**（窗口 70 → 96）：三横杠图标仍画在 6×5
  栅格上、每格从 6px 放大到 9px —— 整数倍放大保住刀切边缘，不出现半像素灰边。
- **新增 `PANEL_READABLE_CSS`（只在面板窗口注入）**：页签 / 功能按钮 / 资源

- **面板高度放宽 1.45 倍**（宽度仍跟电视成套）：字放大之后标题、资源条、
  两行页签要占 200px 出头，按电视原高窗口里只剩一条缝、一打开全靠滚动。
  加出来的高度全部给内容区。
- **顺带修一个叠窗 bug**：电视靠左时控制按钮会翻到电视右侧 —— 正好压在
  面板窗口的右上角（用户截图抓到）。`placePanel` 现在检测按钮在右侧时，

- **修一个高度链 bug**：面板窗口加高后 `#stage` 纹丝不动 —— 它的
  `height:100%` 折在自适应高度的父级上，退回了页面公式 `100vw*9/16`。
  `PANEL_ONLY_CSS` 里把 `html/body/.shell/#playerFrame` 一路 100% 下来才通。

# 2.5.0 · 控制按钮与观测面板都搬到窗口外

画面里的功能按钮看不清也点不准，这一版把按钮和面板都搬到电视窗口外面。

## 起因：0.46 倍的缩放

电视窗口的布局视口恒为 1120px，中档窗口只有 520px 宽，缩放系数 0.46。
画面右上角那排功能按钮（强化 / 技能树 / 档案 / 设置）的字本来 12px，
落到屏幕上只剩 **5.6px**。

这不是"按钮做得不够大"，而是**任何待在被缩放画面里的 UI 都不可能看清**。
所以解法只有一条：让它离开缩放。

## 改了什么

- 新增 `dock.html` + `dock-preload.js`：一个 64px 的像素风按钮，
  住在独立窗口里，所以它有多大就是多大。粗颗粒的做法是全部用整数像素描边、
  阴影一律不带模糊（`6px 6px 0`），图案画在 6×5 栅格上再整数倍放大。
- 新增 `tv:panel` 通道：`tv-preload.js` 用 `MutationObserver` 盯住
  `#management` 的 `hidden`，面板一开一关就上报主进程。
- `main.js` 新增控制按钮与面板窗口的创建、跟随、开关：
  - 按钮贴着电视窗口外侧，窗口一动就重新摆；左边顶到屏幕边缘翻到右侧，
    两边都挤不下时退到窗口内部左下角（宁可压住一点画面，也不能让按钮跑到屏幕外）。
  - 点按钮 → **另开一个面板窗口**（`min(1, 可用高度 / 736)` 定缩放、居中），
    不是把电视窗口放大。电视那边从头到尾不动。
  - 面板关掉 → 收走窗口，按钮继续贴着电视。
  - 窗口收起/展开时按钮跟着一起收放；改档位或回位时重新摆。
- 新增 `panel-preload.js`，面板窗口的存档层。它跑的是**第二份 game.js**，
  所以必须和电视那边分工明确：
  - **只读**：`setItem` 只更新内存、绝不落盘。落盘由电视窗口独占 ——
    两个实例都写文件的话会互相覆盖，谁后写谁赢，另一个还拿着旧数据继续跑，
    而磁盘上看不出任何异常。
  - **操作转发**：面板里的点击/变更按元素 id 转给主进程，由主进程在**电视窗口**
    里执行同一个元素。游戏的权威状态在电视那边，面板只是个遥控器；
    少了这一步，面板里的强化就只是"改了个内存数字给人看"。
  - 转发跳过 `open-*` 入口，否则电视窗口也会跟着弹一个面板出来。
- 新增 `TV_HIDE_DOCK_CSS`：藏掉画面里那排原按钮。**这是整个工程唯一改变
  画面呈现的注入**，理由见下。

## 关于那条唯一的例外

藏按钮确实改了画面的外观，所以它被单独拎出来管：

- 和 `TV_DRAG_CSS` 分成两个常量，绝不合并 —— 合并了的话
  "注入不改变呈现"这条不变式就永远说不清。
- 新增两条断言：隐藏规则里只许出现 `display`（出现 `color` / `font` /
  `width` / `opacity` 之类就失败）；拖动规则里不许出现 `display`。
- 想还原只需要删掉这一条规则，画面本身没有任何残留改动。

之所以用注入而不是去改 `tv/`：`tv/` 依旧一个字节都没动。

# 2.4.0 · 只留电视画面，存档接管到文件

删掉「底座模式」，桌宠只剩一种形态：一台播放 `tv/` 的小电视。
同时把画面的存档从 localStorage 接到文件上 —— **`tv/` 里一个字节都没改**。

## 删除底座模式

「底座模式」是透明悬浮窗里重画的迷你场景（哥斯拉站在一截城市断面上），
属于早期试过又放弃的方案。这一版把它整个从工程里去掉：

| 删掉的东西 | 量 |
| --- | --- |
| `renderer/`（index.html、pet.css、pet.js、growth.js、rig.js、part-bounds.js） | 2439 行 |
| `assets/parts/`（12 个骨骼部件 PNG）与 `assets/fonts/` | 3.1 MB |
| `preload.js`（它的 contextBridge 只服务底座模式） | 46 行 |
| `build/qa-shot.cjs`、`build/make-part-bounds.py` | 264 行 |
| `tests/growth.test.cjs`、`tests/rig.test.cjs` | 658 行 |
| `docs/growth-ladder.png`、`docs/actions.png` | 1.4 MB |

`main.js` 也瘦了一圈：去掉 `MODES` / `PET_SIZES` 模式表、`switchMode`、
自动穿透与拖动 IPC、`publicFlags`，`state` 从「按模式分档」收敛成
`{ size, pos, alwaysOnTop, hidden }`。`loadState` 保留了三种历史文件形状的
兼容（扁平 → 分模式 → 现在的扁平），升级上来不会因为窗口位置读崩。

`docs/` 只留下 `mini-tv.png`。

## 存档：从底座模式搬到电视画面

之前只有底座模式写文件，电视画面用它自己的 localStorage，两份进度互不相干。
现在只剩一条线，存档自然要跟着画面走。

难点是**画面不能改**。做法是在外面劫持：

- 新增 `tv-preload.js`。画面读写存档的地方总共只有两处
  （启动时同步 `getItem`，每 5 秒 / 切走 / 卸载时 `setItem`），
  接管层只把这**一个键**的读写换接到文件，其余一律原样放行。
- 三条硬约束，都是踩过才知道的：必须是 preload（画面**同步**读档，替换得赶在
  它任何脚本之前）；`contextIsolation` 必须关掉（隔离世界里 `Storage.prototype`
  是另一份对象）；读必须保持同步（异步会让画面先拿新档把世界建起来，
  再被迟到的文件覆盖成第二次初始化）。
- 退出路径用同步 IPC（`sendSync`）：`pagehide` 那一刻没有"稍后"，
  异步回调根本发不出去。日常写入走异步 + 1 秒防抖，不阻塞渲染帧。
- 存档文件从 `pet.json` 改名 `tv.json`，格式变成外面一层桌宠封装
  `{ version, payload }`，`payload` 是画面自己那份 JSON 字符串，原样透传。
- 迁移：文件里没档而 localStorage 里有 → 自动搬一次。
  目录里遗留的旧 `pet.json` 不会被读也不会被删（格式对不上，安静走新档）。

**这次改动最要紧的一条测试**：两边只靠一个字符串常量关联
（`tv/game.js` 的 `SAVE` ↔ `tv-preload.js` 的 `KEY`）。对不上的话接管会
**静默失效** —— 画面照常跑、照常显示"进度已保存"，只是写回了 localStorage，
导出备份时拿到空文件，全程零报错。所以 `tests/tv.test.cjs` 加了四条断言，
不是断言"代码里有这个字符串"，而是把两边读出来对比，并在断言消息里写清后果。

# 2.3.0 · 桌宠主线化与文件存档

从这一版起，仓库以桌宠为唯一主线；原先与它并列的网页版降级成它播放的画面
（`tv/`），不再是需要单独维护的第二条产品线。

## 目录

- `godzilla-shinjuku/` → `godzilla-pet/tv/`。迷你电视不再依赖项目里另一个同级
  目录，`godzilla-pet` 单独拷走就能跑，这条老限制随之消失。
- 单文件离线版从根目录移入 `godzilla-pet/dist/`，与生成的 `.app` 放在一起，
  都算发布产物。
- 根目录的历史文件移入 `archive/`：`雨夜新宿.html`（与 `巨兽都市-挂机直播.html`
  逐字节相同的重名副本，同 MD5）、`雨夜新宿-游戏与源码.zip`（真正的旧街机版）、
  `巨兽都市-挂机版与源码.zip`（已被目录内容取代的旧全量包）。
- 版本号统一到 2.3.0：`package.json` 与 `.app` 的 `CFBundleShortVersionString`
  以前停在 1.0.0，与 `tv/CHANGELOG.md` 里已经走到 2.3 的画面版本号不一致。

## 存档

存档从渲染层的 localStorage 改成主进程管的文件：
`<userData>/save/pet.json`。

- 新增 `save-store.js`：写临时文件 → fsync → 主档改名成备份 → 临时文件改名成
  主档。两次改名都是原子的，因此任何时刻磁盘上至少有一份完整可读的档；
  主档读不出来时自动回退备份。不依赖 electron，目录由调用方注入，可单独测。
- 新增周期落盘：主循环按真实墙钟累积，每 5 秒写一次。**在这之前桌宠没有任何
  自动存档** —— `save()` 只在「页面隐藏」「暂停/静音」「退出」时被调用，
  而挂机游戏恰恰长期处于"窗口可见、无人操作"的状态，几小时不写盘是常态，
  断电或强杀就会丢掉那几小时。
- 新增退出握手：主进程在 `before-quit` 里等渲染层同步写完最后一次进度才真正
  退出（最多等 800ms）。`pagehide` 也改用同步 IPC，因为那一刻没有"稍后"。
- 新增「存档」菜单（托盘与右键共用）：打开存档文件夹 / 导出备份 / 从备份导入 /
  重置存档。导入前先校验来源文件，坏文件不可能把好档顶掉；导入与重置都会先确认。
- 新增一次性迁移：首次启动时若文件存档不存在而 localStorage 有旧档
  （键 `gnn-pet-v1`），自动搬进文件并提示一次。浏览器预览没有主进程时，
  仍回退到 localStorage。
- 存档新增两个长期字段：`bornAt`（第一次见面）与 `sessions`（累计启动次数）。
  老存档没有 `bornAt` 时用累计陪伴时长倒推（出生 = 现在 − 陪了多久）。
  版本号保持 1，老存档照常读。

## 其它

- 异步读盘之后，「页面加载完」不再等于「宠物已经在了」。新增
  `window.__petDebug.ready` 供 QA 脚本判断世界是否建立，`qa-shot.cjs`
  改为轮询它而不是猜一个 sleep 时长。
- `qa-shot.cjs` 注入等级不再改 localStorage 再重载（还要把 `setItem` 换成空函数
  以防止卸载回写覆盖注入值），改为建一个临时存档目录、先写好目标存档再打开窗口。
  少了两步绕路，而且顺便验了真实的文件存档路径。工具只用临时目录，
  绝不碰用户自己的存档。
