# 巨兽都市桌宠 · godzilla-pet

一个小电视，常驻在桌面角落，里面一直在播哥斯拉拆新宿。它自己走路、自己拆楼、
自己进化，从只能拍碎平房的幼体慢慢长成能一脚踩平高楼的完全体。全程不需要你操作，
进度会一直留着。

**桌面上看到的画面，是 `tv/` 里那份游戏原封不动播出来的** —— 桌宠不复制、
不改写它的任何一个字节，只用 `loadFile` 把那个页面打开，然后整体等比缩小。
桌宠真正自己写的，只有外面那圈窗口、托盘、以及**把它的存档接到文件上**。

```bash
npm install                  # 装依赖（Electron 运行时）
npm start                    # 前台跑一个，调试用
sh build/make-app.sh         # 装成可双击的应用 → ~/Applications/巨兽都市桌宠.app
```

`npm start` 是从终端直接跑，**终端一关它就没了**，只适合调试。
日常用请走 `make-app.sh` 装成真正的应用：双击即开，不占 Dock、不在 Cmd-Tab 里，
退出走托盘菜单或 `⌘Q`。

> **不能直接把项目目录当应用使。** Electron 必须把项目目录作为启动参数才能
> 加载我们的主进程，而通过 LaunchServices 启动时（双击 / open / 登录项）
> macOS 会自己往参数里塞东西，路径根本到不了 Electron，它就退回自带的欢迎页
> ——不报错，只是"双击打开的是一页英文说明"。所以 `.app` 里包了一层启动器
> 自己拼 argv，安装位置也必须是 `~/Applications` 而不是项目目录。
> 两个原因都写在下面的坑一里。

## 存档

**存档是一个文件**：`<userData>/save/tv.json`。macOS 下完整路径是
`~/Library/Application Support/巨兽都市桌宠/save/tv.json`。
它长这样，外面是桌宠的封装，`payload` 才是画面自己那份进度：

```json
{
  "version": 1,
  "payload": "{\"version\":3,\"energy\":10038.1,\"level\":8,\"district\":10,...}"
}
```

托盘菜单 →「存档」里能看到它、导出它、换掉它：

| 菜单项 | 做什么 |
| --- | --- |
| 打开存档文件夹 | 在访达里定位到那个目录 |
| 导出备份… | 把当前存档拷到你想放的地方，用来换机器或防手滑 |
| 从备份导入… | 拿一份导出的 JSON 顶掉现在这份（会先问一次） |
| 重置存档… | 主档和备份一起删，从头开始（会先问一次） |

### 为什么是文件，不是 localStorage

画面原本存在浏览器的 localStorage 里（键 `gnn-kaiju-idle-v3`）。三个问题：

1. localStorage 是页面私有的，清一次缓存、换一个 profile 就跟着走了。而这是个
   要挂几个月的游戏，存档得是用户**能看见、能备份、能搬走**的东西。
2. localStorage 没有原子性也没有备份。写到一半断电就是一个坏掉的 JSON，
   而画面自己的 `sanitize` 遇到坏档会整体回落到 1 级——几个月的进度就没了。
3. 主进程掌控窗口生命周期，能在退出、崩溃、系统重启前把数据落盘。

### 存档是怎么接管过来的

**难点在于 `tv/` 一个字都不能改。** 那份画面是"被播放"的素材，改了它就不再是
原封不动的原版；但我们又要让它把进度交出来。所以不能去动它的代码，
只能在它外面劫持。

画面读写存档的地方总共只有两处（`tv/game.js` 里）：

```js
// 启动时读，同步
raw = JSON.parse(localStorage.getItem('gnn-kaiju-idle-v3') || 'null')
// 每 5 秒 / 切走窗口 / 页面卸载时写
localStorage.setItem('gnn-kaiju-idle-v3', economy.serialize(Date.now(), worldSnapshot()))
```

于是 `tv-preload.js` 只做一件事：**把这一个键的读写换接到文件上**，
其余读写一律原样放行。画面完全不知道自己已经不在跟 localStorage 打交道了。

三个设计上的硬约束：

| 约束 | 为什么 |
| --- | --- |
| 必须是 preload | 画面在**启动时同步**读档。替换得赶在它任何脚本之前完成，只有 preload 卡在这个位置 |
| `contextIsolation` 必须关掉 | `Storage.prototype` 在隔离世界里是另一份对象，改它影响不到页面 |
| 读必须保持同步 | 换成异步 API，画面会先拿着一份新档把世界建起来，再被迟到的文件覆盖成第二次初始化 |

写盘那边：`setItem` 只写内存并标脏，防抖 1 秒后推给主进程；
而 `pagehide` / `visibilitychange` 这两个"等不到异步回调"的时刻走**同步** IPC
（`sendSync`），对应画面自己在调 `save()` 的那两个时机。

> 关掉 `contextIsolation` 是有代价的，这里是权衡后的选择：页面是本地文件、
> 没有任何网络内容，而 `nodeIntegration` 仍然是 `false`（页面拿不到 `require`），
> preload 里的 `ipcRenderer` 也只是模块作用域的局部变量，不会挂到 `window` 上。

两边靠一个**字符串常量**关联：`tv/game.js` 里的 `SAVE` 和 `tv-preload.js` 里的
`KEY`。一旦对不上，接管会**静默失效** —— 画面照常跑、照常显示"进度已保存"，
只是写回了 localStorage，导出和备份全部落空，谁都不会报错。
`tests/tv.test.cjs` 专门钉住了这个常量必须一致，以及"画面仍然是同步读档"
这个前提。

### 什么时候写盘

| 时机 | 方式 | 说明 |
| --- | --- | --- |
| 每 5 秒 | 异步 | 画面自己的节奏；接管层再防抖 1 秒合并密集写入 |
| 窗口隐藏 | **同步** | 切走时顺手存一次 |
| 页面即将卸载 | **同步** | `pagehide` 那一刻没有"稍后"，异步回调根本来不及跑 |
| 导入之后 | — | 整页重载，让 preload 重新握手取到新档 |

崩溃、强杀最多丢 5 秒。正常关窗走的是同步那条，实测**一次都不会丢**：
关掉窗口后文件时间戳会立刻冻结在那一刻，而不是等到下一个 5 秒周期。

> 导入存档时有一段闸门：页面卸载也会触发一次同步落盘，那一次写会把刚导入的档
> 又盖回旧数据。所以在导入成功到画面下一次握手之间，写盘一律拒绝。

### 写坏了会怎样

`save-store.js` 的写入顺序固定是「写临时文件 → fsync → 主档改名成备份 →
临时文件改名成主档」，两次改名都是原子的，所以任何时刻磁盘上至少有一份
完整可读的档：

| 崩在哪 | 磁盘状态 | 下次读到的 |
| --- | --- | --- |
| 写临时文件途中 | 主档完好 | 旧档 |
| 临时文件写完、还没改名 | 主档完好 | 旧档 |
| 主档已改名成备份 | 备份完好 | 备份 |
| 临时文件已改名成主档 | 主档是新档 | 新档 |

代价是备份永远落后一个存档周期（5 秒），换来的是**永远不会读到半个 JSON**。
主档读不出来时自动回退备份，备份再读不出来就当新档从头开始——不弹错、不卡启动。
导出时会**按"读得出来"挑来源**而不是"文件在不在"：主档损坏时它会把备份救出来，
而不是让你拿到一个同样打不开的文件还以为救下来了（这条有回归测试）。
导入之前会先校验来源文件，坏文件不可能把好档顶掉。

### 存了什么

外面那层只放 `version` 和 `payload`，进度字段全部由画面自己定义、原样透传：

```
能量 energy · 累计 earned · 经验 xp · 等级 level · 突变点 dna
城区 district · 已清理 cleared · 击杀 kills · 行进距离 meters
四项强化 levels · 已解锁技能 skills · 自动进化 auto · 策略 policy
静音 muted · 上次在线 lastSeen · 城市快照 world
```

`payload` 保持**字符串**而不是解析后的对象——它就是 localStorage 里原本的那个值，
原样存取才不会在往返中丢掉画面那边的字段。

### 从旧版升级

以前存档在 localStorage，而且底座模式那会儿文件叫 `pet.json`。现在启动时：

- 文件里没档、而 localStorage 里有 → **自动搬进文件**，只搬一次。
- 目录里遗留的 `pet.json`（旧底座模式的成长数据）不会被读，也不会被删——
  格式对不上，桌宠认的是 `payload`，它会安静地走新档那条路。

## 迷你电视

窗口里播的就是 `tv/` 那份游戏：像素新宿夜景、GNN 直播包装、
滚动新闻条、转台式雪花换场，连它自带的进化系统、离线收益、自动战斗全都照旧。

![三档尺寸](docs/mini-tv.png)

> 三档 1:1 实尺寸，默认中档 520×342，屏幕上的画面 505×284。

做法是给窗口一个「桌面宽度」的**布局视口**，再用缩放系数把整页等比缩小：

```
窗口内的布局视口恒为 1120 × 736
缩小系数 = 窗口宽 / 1120
窗口尺寸 = 1120 × 736 × 系数
```

**为什么不直接把窗口缩到 500px 宽？** 因为原版有一堆固定像素（页眉 46px、
页脚 38px、正文字号 12px），窗口真缩到那个宽度会撞上它自己的
`@media(max-width:680px)`，版面会切成另一套——画面铺满视口、页脚消失。
保持桌面宽度的视口再整体缩放，比例才和原版逐像素一致。

视口必须同时满足两条：宽度 > 1050px（绕开 1050 / 680 两个窄屏断点）、
高度装得下页眉 + 画面 + 页脚（≥704px，否则出滚动条）。在这两条之内，
视口越贴近画面的实际尺寸，四周留白越少——1120×736 是实测留白最少、
上下左右又均匀的一档。用 1280×720 的话 `.shell` 只有 1104 宽，左右会各空出
88px 黑边。

`tests/tv.test.cjs` 把这些不变式钉住了：只改档位宽度、忘了跟着算高度，
测试会直接报出来——那正是最容易犯、后果最隐蔽的错。

拖动靠注入一条 `-webkit-app-region` 规则：**拖动区恰好是三块** —— 上（台标条
`.tv-brand`）、右（大电视 `#playerFrame`，含画面）、下（页脚 `footer`）；左侧控制栏
`.tv-sidebar`（遥控器 + 换台两个按钮）**整块没有拖拽区**。能被点到的控件
（`button` / `select` / `input` / `label`）另标成 `no-drag`，观测面板里的按钮照旧点得动。

2026-09-18 之前不是这样：那时 `.shell` 是 `no-drag`，能拖的只剩柜外那圈留白
与上下两条状态栏，等于逼玩家去够两条窄边，压住画面正中反而拖不动。
2026-09-18 改成"整柜可拖 + 侧栏挖个洞"，结果**两个按钮点不动了** —— 见下面那条实测。

> ⚠️ 这条是拿真窗口问系统问出来的，不是推断：**"大祖先 drag + 子级 no-drag 挖洞"
> 在这台 Chromium 上不成立**。把真机窗口起起来对若干锚点逐个问 WM_NCHITTEST，
> 结果是 `body` 上一旦出现任何声明，整窗判定就退化成"全听 body 的"（`body{drag}`
> 时侧栏也是 HTCAPTION，`body{no-drag}` 时连画面的 drag 也失效）；`.shell{drag}`
> 时作为它**兄弟**的侧栏同样挡不住。
> 所以 `TV_DRAG_CSS` 里 **`body` 与 `.shell` 一个字都不许写**，拖动区只能落在三块
> **互不包含**的区域上。现象是"按钮点了没反应"，两端不报错 —— 光读 CSS 看不出来。

三条不变式各有断言盯着：

- 注入里**不许有任何视觉属性**（出现 `color` / `font` / `margin` 之类直接失败）；
- 「恰好这三块能拖、`body`/`.shell` 声明为空、侧栏与控件不可拖、面板窗口不可拖」
  由 `tests/tv.test.cjs` 按规则块逐条断言；
- **控件有没有被拖动区吞掉**由 `build/tv-shot.cjs --tv` 的 `REGION*` 审计实测 ——
  它沿祖先链回算每个可见控件的有效归属，落到 `drag` 上直接失败。这类故障的现象是
  "点了没反应"，两端都不报错，只看 CSS 文本是看不出来的。

> 一个必须记住的性质：`-webkit-app-region` 是**继承属性**，而面板窗口是同一个页面
> 另开的一份，整页就是 `.shell`。所以面板那条 `html.panel-view .shell { no-drag }`
> 是保底：哪天有人给 `body` / `.shell` 加回一条 `drag`，面板会顺着继承沾上，
> 滚动条与滚轮一起被吞掉。

### 电视柜以外透出桌面

窗口里那圈留白**不是黑边，是桌面**。要做到这一点得同时改**两层**，少一层就还是黑的：

| 层 | 在哪 | 怎么改 |
| --- | --- | --- |
| 窗口层 | `main.js` 电视窗口 | `transparent: true` + `backgroundColor: '#00000000'` |
| 页面层 | `tv-config.js` 的 `TV_TRANSPARENT_CSS` | 把 `html, body` 那两层 `#050a15` 抹成 `transparent` |

只改窗口层：页面自己刷的 `#050a15` 铺满整个视口，照样是黑的。
只改页面层：窗口底板还在，一样黑。**两层都动才算数**，所以有断言各钉一层。

留白有多厚，是版面算出来的（视口 1120×736，`.shell` 只有 1088×625 并垂直居中）：

| 方向 | 视口里 | small 档（×0.4）实到屏幕 |
| --- | --- | --- |
| 左右 | 各 16px | 各 6.4px |
| 上下 | 各 55px | **各 22px** |

上下比左右厚三倍多 —— 这就是原来那圈黑边"上下明显更宽"的来源。

三条边界：

- **面板窗口故意不透明**，也不注入 `TV_TRANSPARENT_CSS`。它是一块摆在电视旁边的
  菜单，字压在壁纸上只会更难读。断言数 `insertCSS(TV_TRANSPARENT_CSS)` 恰好一次。
- **只碰 `html, body`**，不碰 `.tv-cabinet` / `#playerFrame` 这些画面本体 ——
  一旦碰到，那就从"改窗口"变成"改产品定义"了。断言钉着选择器白名单。
- **留白区域看不见但仍属于窗口**，鼠标移到那圈"空气"上照样被窗口接住。
  换掉它要 `setIgnoreMouseEvents` + 逐区域动态开关，收益不抵复杂度，不换。

至于柜子周围那圈**深浅渐变**（贴着圆角轮廓、越往外越淡），那是 `tv/style.css` 里
电视柜自己的 `box-shadow`，属于画面的一部分，不是窗口底色。

## 控制按钮与观测面板

电视窗口**外面**贴着一个 88px 的像素方块，那是全部功能的入口。点它，旁边会
**多出一个面板窗口**——宽度跟电视成套、高度放宽的一块"遥控屏"，里面只有
观测面板本身（加点 / 天赋 / 进化 / 数值强化 / 技能树 / 档案 / 设置，游戏自己
的那套菜单，字与按钮整体放大了一号）；看完点「× 返回直播」或按 Esc，
面板窗口收走。**电视窗口从头到尾不动一个像素，一直在那儿播。**

**为什么按钮和面板都非要待在窗口外面。** 电视窗口把 1120px 的视口缩到 520px，
缩放系数 0.46 —— 画面里任何东西都会被砍掉一半多。原来那排功能按钮的字落到
屏幕上只剩 **5.6px**，既看不清也点不准。想保持可读，就只能待在缩放之外。

几个实现上的取舍：

| 做法 | 为什么 |
| --- | --- |
| 按钮是**独立窗口** | 只有独立窗口能待在缩放之外。它贴着电视窗口外侧，跟着窗口一起移动；左边顶到屏幕边缘就翻到右侧 |
| 面板**也是独立窗口**，不是把电视窗口放大 | 把电视放大，小电视就没了 —— 而它本来就该一直挂在那儿播 |
| 面板**不缩放（zoom 钉死 1）**，让游戏自己的窄屏紧凑断点接管 | 游戏在 `max-width:680` / `max-height:480 横屏` 各有一套紧凑布局，正好命中面板窗口的形状 —— 字号回到真实的屏幕像素。这条必须**显式**设：Chromium 把缩放按来源存在会话里，面板会静默继承电视窗口设过的 0.41 |
| 面板里**只留观测面板**（`PANEL_ONLY_CSS`，只在面板窗口注入） | 直播包装（台标、机位、滚动新闻条、页脚）在菜单里全是噪音；`#stage` 同时解除 16:9，让菜单铺满窗口。电视画面不受影响 |
| 面板里**字与按钮整体放大一号**（`PANEL_READABLE_CSS`，同样只在面板注入） | 游戏的紧凑断点是为 680px 宽的浏览器设计的，落到面板里偏小。放大用**原生像素**而不是整窗 zoom —— 非整数倍的 zoom 会把像素字体的笔画缩得忽粗忽细，颗粒感就没了。与上一条分成两条独立常量，各有契约测试 |
| 面板**宽度跟电视成套、高度放宽 1.45 倍** | 字放大之后标题、资源条、页签要占 200px 出头，按电视原高打开面板只能看见一条缝。加出来的高度全部给内容区；高度必须从 `html/body/.shell/#playerFrame` 一路 100% 下来，`#stage` 才跟得上窗口 |
| 面板加载的是**同一份 `tv/` 页面** | 菜单连同全部交互都是画面原装的，一行都没重写 |
| 面板的存档是**只读的** | 两个窗口跑同一份 `game.js`，都会调 `save()`。都写盘就会互相覆盖 —— 谁后写谁赢，另一个还拿着旧数据继续跑，而磁盘上看不出任何异常 |
| 面板里的操作**按白名单转发**给电视窗口执行 | 游戏的权威状态在电视窗口那个实例里，面板只是个遥控器。白名单只收「会改游戏状态」的控件 —— **切 tab、关窗绝不转发**：`talentTab` 也带 `talent` 前缀，正则一旦放行，面板里切个页就会让电视机弹出自己的面板，直播被功能页盖住（真实发生过，有契约测试钉着） |
| 关闭监听 `hidden` 属性 | 面板有三个出口（`× 返回直播`、Esc、将来别的），盯属性是唯一能全覆盖的做法 |

> 代价说清楚：那条藏掉画面里原按钮的 CSS，是整个工程**唯一**改变画面呈现的
> 注入。它是产品决定而不是修 bug —— 测试里单独断言，只许动 `display`，
> 出现颜色或字号就会被拦下来；拖动那条也单独断言不许夹带 `display`，
> 两条注入不许混在一起。

三个测试文件各有分工：`tv.test.cjs` 管档位不变式（视口必须越过窄屏断点、高度
必须等于视口高 × 系数、注入内容里不能出现视觉属性）**以及存档接管的契约**
（劫持的键必须与画面里的 `SAVE` 一致、画面必须仍是同步读档、只换掉那一个键、
退出路径必须是同步写）；`save-store.test.cjs` 管存档的持久化性质（写入原子、
坏档回退备份、坏数据不许覆盖好数据、`payload` 逐字往返、连续写入 50 次不漂移）；
`app-bundle.test.cjs` 管"怎么把应用启动起来"（启动器必须把项目目录传给
Electron、`PROJ` 必须是写死的绝对路径、装着的位置错了必须警告）。

> 存档接管那组断言尤其重要：**它失联的时候不会报任何错**，只是进度悄悄写回了
> localStorage，肉眼完全看不出来。

`app-bundle.test.cjs` 会真的跑一遍 `make-app.sh` 装到临时目录再检查产物，
所以它验证的是生成出来的东西，不是源码里有没有某句话。装到临时目录而不是
项目目录，也顺便保证了它不会顺手杀掉你正在看的那个桌宠。

截图工具跑的都是真实 Electron 运行时：

```bash
# 按档位抓图，顺便回读版面实测值与 app-region
env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron build/tv-shot.cjs \
  --size=medium --tv --out=/tmp/tv.png
```

`tv-shot.cjs` 支持 `--size=small|medium|large`、`--tv` 注入拖动区域并回读
`app-region`、`--w`/`--h`/`--zoom` 手动指定、`--wait` 抓图前等待毫秒数、
`--pad` 给窗口留白上色（默认洋红，一眼看出画面占了多少）。

想核对**已经装好、正在运行**的那个窗口里究竟加载了什么，用 `cdp-probe.cjs`。
应用是 GUI 程序、没有终端，所以调试端口靠环境变量递进去：

```bash
launchctl setenv GNN_DEBUG_PORT 9222
open -a "$HOME/Applications/巨兽都市桌宠.app"
node build/cdp-probe.cjs 9222      # 打印页面 URL、视口、缩放、拖动区域
launchctl unsetenv GNN_DEBUG_PORT
```

不设这个变量时端口完全不开，正常使用不受影响。

> 注意：如果环境里带着 `ELECTRON_RUN_AS_NODE=1`，Electron 会退化成纯 Node，
> 主进程里的 `app` 会变成 `undefined`，`main.js` 第 40 行直接
> `TypeError: Cannot read properties of undefined (reading 'setName')`。
> 所有 Electron 调用前都要 `env -u` 清掉它。这个变量常见于被人从
> Electron 应用里派生的子进程，自己的终端里一般没有。

## 踩过的三个坑

这三个的共同点是**都不报错**。第一个看起来像"双击没反应"，
第二个看起来像"我明明挂了一整天"，第三个看起来像"得点两次"——
都只能靠诊断数据才抓得出来。

### 一、双击打开的是欢迎页，或者干脆什么都不发生

这条最花时间，因为它有**两个毫不相干的成因**，表现还都很安静。

**（1）启动参数到不了 Electron。** 从终端直接跑
`electron <项目目录>` 是正常的；但换成 `open`、双击或登录项，argv 就不再由
我们掌控：

```
open -a Electron.app --args <项目目录>   → 只出欢迎页，main.js 根本不执行
launchctl submit -- Electron <项目目录>  → 被沙箱拒绝，不可用
```

两个都是实测结论。所以 `.app` 的 `CFBundleExecutable` 是一个我们自己写的
启动器，由它来拼 argv：

```sh
exec "$ELECTRON" "$PROJ"     # 这一行就是整个包装存在的理由
```

漏掉 `"$PROJ"` 就会退回欢迎页，而且没有任何报错。

**（2）装在 `~/Documents` 里会卡死在启动早期。** 同一个 `.app`：

| 位置 | 结果 |
| --- | --- |
| `~/Documents/.../godzilla-pet/dist/` | 主进程活着，但**不起任何渲染/GPU 子进程**，窗口不出现，也从不写存档；零报错、零日志，`lsof` 能看到它已加载 Electron Framework，就是走不下去 |
| `~/Applications/` | 一切正常 |

原因是 macOS 的「文稿」隐私保护：位于受保护目录内的 app 包，读取自身资源
会被拦，而 Chromium 要 fork 渲染/GPU 子进程，于是卡死在启动早期。所以安装
目标是 `~/Applications`——桌面应用本来就该待的地方，而不是项目内。
`make-app.sh` 在你把目标设成项目目录时会明确警告。

`tests/app-bundle.test.cjs` 把这个包的契约钉住了：启动器必须把项目目录作为
第一个参数交给 Electron、`PROJ` 必须是写死的绝对路径且真的指向本项目、
`LSUIElement` 必须为真、装到坏位置时必须有警告。

### 二、接管装上了，但进度还是写回了 localStorage

接管层一旦和画面对不上，**不会有任何症状**：画面照常跑、照常显示
"进化进度已保存"，一切看起来都正常，只是那份"保存"落在了 localStorage 里，
你导出备份时拿到的是空文件。不会有报错、不会有崩溃、也不会有 UI 变化。

两边唯一的关联是一个字符串常量：

```js
tv/game.js      const SAVE = 'gnn-kaiju-idle-v3'
tv-preload.js   const KEY  = 'gnn-kaiju-idle-v3'
```

所以这条被单独钉进了测试——不是断言"代码里有这个字符串"，而是把两边**读出来
对比**，同时在断言里说清楚对不上的后果。同类断言还有两条：画面必须仍然是
`localStorage.getItem(SAVE)` 这种同步读（preload 的同步握手依赖这个前提），
以及 `pagehide` 上必须挂着同步落盘（异步 IPC 在页面卸载时根本发不出去）。

这个坑的教训可以推广：**跨进程、跨文件、跨语言的隐形契约，必须有一条会失败的
断言盯着。** 光靠注释说明，几个月后没人记得。

### 三、"要点两次才能打开"，以及那三条不能删的 GPU 参数

现象：双击 `start-godzilla.bat` 之后，再点一次游戏才出来。

结论是：**不是需要点两次，是第一次点击之后那几秒里，屏幕上一个能认出来的东西都没有。**
两次点击各自实际做了什么 ——

| 第几次 | 实际动作 |
| --- | --- |
| 第 1 次 | 新进程启动、拿到单实例锁、建窗口。但窗口是 `transparent` + 全透明底色，而抹掉页面底色的 `TV_TRANSPARENT_CSS` 要等 `did-finish-load` 才注入 —— 在那之前桌面上**没有任何轮廓** |
| 第 2 次 | 新进程拿不到锁 → `app.quit()`。这句在 `app.whenReady()` **之前**，`initObservability()` 根本没跑，所以**一行日志都不留**；唯一动作是给第一个实例发 `second-instance` → `toggleVisible(false)`，而窗口已显示时 `showInactive()` 是空操作 |

所以**"第 2 次"在日志里查不到**，这本身就是判据：`main.log` 里
「电视窗口已创建」前面没有「启动」行 = 同进程重建窗口（second-instance 或托盘左键），
不是新进程启动。

实测（隔离 userData，脚本模拟"1.4 秒后再点一次"，连跑 4 次）：第 2 个进程每次都是
干净退出、零日志；「电视窗口已创建」始终只有 1 条。**第二个进程还会显著拖慢第一个** ——
同一份构建，无人打扰时"窗口创建 → 页面就绪"约 2.0 s，而第二个进程在旁边启动时
同一指标涨到 17.0 s。也就是说"再点一次"不只是没用，它让等待更长。

**修法两处**（都在 `main.js` / `tv-config.js`，没碰 `tv/`）：

1. `TV_STARTUP_CSS` —— `dom-ready` 时先给 `html/body` 刷一层不透明底，等
   `did-finish-load` 再由 `TV_TRANSPARENT_CSS` 覆盖回透明。两条的选择器与
   `!important` 完全相同，靠**后插入者胜**收敛回去，因此**注入顺序不能调换**；
   反过来就是一块永远不透明的深色矩形，透明效果整个失效。
2. `second-instance` 补一次显式 `show()` + `focus()`。原来的 `toggleVisible(false)`
   在"窗口已存在"时是空操作，玩家点完毫无反馈。

顺带补掉一个重入缺口：`createWindow` 有两个入口（whenReady 的首次创建、
second-instance 里发现没窗口时的重建），两者之间原本没有互斥，而
`new BrowserWindow` 是同步的、要几百毫秒到两秒半 —— 重建请求落在首次创建
`win = w` 之前，旧的那句 `if (win && !win.isDestroyed())` 就挡不住，同一个进程会
建出两个窗口（只有后建的那个被 `win` 引用，先建的从此没人管得了）。
现在外面套了 `creatingWindow` 闸门，真正的实现在 `buildWindow`。

**那三条参数不要删。** `--in-process-gpu --disable-gpu --no-sandbox` 在
`start-godzilla.bat` 和 `package.json` 的 `start` 里都有。它们看着像沙箱适配的遗留，
2026-09-18 试过删掉，**删了就崩** —— 同一份构建、同一份隔离 userData、
唯一变量是这三条：

| 参数 | 结果 |
| --- | --- |
| 带 | 窗口出现、页面加载、正常运行 |
| 不带 | 进程在「电视窗口已创建」之后**立刻死**，退出码 `0x80000003`，页面从未加载 |

它们也**不是**启动慢的原因。不带沙箱实测"窗口创建 → 页面就绪"只要 **441 ms**。
`AppData` 日志里 5~10 秒的冷启动另有原因，与这三条无关 —— 存档大小已排除
（有档 2063 ms / 空档 2074 ms），剩下的指向当时的机器负载。**两个入口的这三条必须一起留**，
改一处不改另一处会让"双击"和"npm start"表现不一致。

## 已知限制

- `.app` 里写死了项目目录的绝对路径（包已经离开项目目录，相对路径会失效）。
  把项目挪走之后要重新跑一次 `sh build/make-app.sh`，否则启动时会弹提示。
- 应用必须待在 `~/Applications` 这类不受隐私保护的位置。装进 `~/Documents`
  会卡在启动早期：主进程活着但不起渲染子进程，窗口不出现也不写存档。
- 窗口尺寸只有小 / 中 / 大三档，不支持拖拽缩放：缩放系数必须跟着窗口宽度重算，
  自由拖拽会让版面在拖动过程中反复重排。
- 托盘图标只有 16px，细节一律糊掉，所以做的是剪影而不是写实哥斯拉。
- 存档接管依赖画面里的 `SAVE` 常量与"启动时同步读档"这两个前提。
  换一份画面版本时，`tests/tv.test.cjs` 会先报出来。
- 打包成独立应用要用 `electron-builder` 之类的工具，本仓库的 `make-app.sh`
  生成的是 macOS 启动器，不是自包含的包。
- 电视窗口的留白是透明的，但**那块地方仍然算窗口**：鼠标移到柜子外那圈"空气"上
  会被窗口接住，点不到底下的桌面图标。要改得用 `setIgnoreMouseEvents`
  加逐区域动态开关，本版不做。
- 透明窗口在 macOS 上可能留下视觉残影（Electron 为此提供 `invalidateShadow()`）。
  本项目会改窗口尺寸（`applySize`）与拖动位置，属于容易触发的情形。**未在
  macOS 上实测**，记在 `docs/平台验证清单.md` 里。Windows 侧无此文档化条目。
