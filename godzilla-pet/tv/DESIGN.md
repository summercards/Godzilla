# 设计说明：从横版操作到挂机演出

## 体验目标

打开即可观看巨兽摧毁城市，新闻以军方和现场记者视角连续报道。破坏提供资源，资源改善效率，强敌带来新的压制，形成持续观看和进化动机。游戏不通过玩家死亡中断观看。

## 核心循环

自动观察目标 → 接近防线 → 技能破坏 → 核能与经验 → 数值强化 / 技能突变 → 区域突破 → 更强防线。

### 自动决策

每帧推进动作状态机，按顺序判断：近距离重踏、侧后方尾扫、密集敌军震慑、近身爪击、可用吐息与远处射线目标、继续行走。技能动作存在蓄力、命中和收势阶段，伤害绑定具体时点，而非仅播放特效。

近战接触以骨骼上的实际爪端、脚部和尾端为准。主街建筑需进入爪端前方约 70 像素内才会被爪击，行动 AI 在建筑前缘距离躯干约 180 像素时才停止前进；避免巨兽隔着明显空隙挥爪。重踏与尾扫仍是范围攻击，保留更大的画面表现范围。

新闻直播大横幅只在封锁突破、重踏、咆哮或原子吐息等重大事件出现，停留 4 秒后收起；常态只显示底部细新闻条。炮弹命中巨兽时触发约 0.18 秒的红色像素闪光和轻微后坐，作为受击反馈，不引入玩家血条或失败状态。

- 爪击约 1.18 秒，0.54 秒命中。
- 吐息约 4.2 秒，0.95–3.55 秒持续输出。
- 重踏约 1.68 秒，1 秒命中。
- 咆哮约 2.1 秒，0.45 秒产生震荡。
- 尾扫约 1.65 秒，0.83 秒命中。

重踏 12 秒、咆哮 25 秒、尾扫 15 秒、吐息 28 秒冷却，从施放起计时；原始觉醒将冷却缩短 25%（吐息仍为 21 秒）。每区首次吐息等待 18 秒。近处目标的近战优先级高于就绪的吐息。AI 不依赖键盘、鼠标点击或触摸战斗按钮。

## 数值与资源

令 L 为进化等级，M = 1 + (L−1)×0.07。**M 只放大挂机收益（核能产出），不放大攻击力** —— 攻击力自 2.7 起不再随等级膨胀，见下表与「攻击力为什么不涨」。

| 项目 | 初始 / 规则 |
| --- | --- |
| 初始核能 | 180 |
| 强化价格 | 初始价格 × 1.22^(当前强化等级−1)，取整 |
| 力量初始价格 | 80 |
| 炉心初始价格 | 95 |
| 代谢初始价格 | 70 |
| 动能初始价格 | 90 |
| 爪击基础伤害 | (54 + 力量等级×22) × [1+(区域−1)×0.22] |
| 吐息每秒基础伤害 | (85 + 炉心等级×30) × [1+(区域−1)×0.22]，另有炉心强度增长 |
| 基础行进速度 | 30 + √动能等级×8 |
| 被动核能 / 秒 | (2.5 + 代谢等级×1.4)×M，受汲取加成 |
| 破坏收益倍率 | 1 + (代谢等级−1)×0.12，受汲取加成 |
| 下一级所需经验 | 260×L^1.28，取整 |
| 升级突变点 | 每次 +1 |
| 区域突变点 | 每次突破 +2 |

### 攻击力为什么不涨

1 级的攻击力就是全程的基准值：等级只改变体型与挂机收益，不改变伤害。旧公式把伤害乘了 `M`，50 级时是初始的 4.4 倍，"1 级即初始状态"这句话在数值上不成立。

伤害改由**区域推进**驱动，倍率 `1+(区域−1)×0.22` 与**建筑耐久共用同一个系数**（这个数住在 `growth.js` 的 `DISTRICT.coef`，`progression.js` 的 `Kb` 直接读它，**不允许在别处再写一份**）。两者同源是硬约束：一旦分叉，推图几十个区域后要么楼变成纸糊的、要么怎么打都打不动，而且不报任何错。

- 攻击力：(54 + 力量等级×22) × districtScale(区域) × (1 + 突变伤害加成)
- 吐息：(85 + 炉心等级×30) × districtScale(区域) × (1 + 突变吐息加成)
- districtScale(区域) = 1 + (区域−1) × 0.22；关掉 `COMBAT.districtScaling` 即回到纯初始状态
- 想回退旧行为：打开 `growth.js` 的 `COMBAT.levelScaling`

敌人经验系数是另一条独立的设计线（`Ke` = 1+(区域−1)×0.19，低于建筑系数），所以巨兽对建筑的效率随区域提升，对人则越来越吃力。这是有意的差，不是漏改。


每三秒，自动进化按偏好选择强化，再尝试解锁一个可用技能节点。手动加点使用同一套价格、资源扣除和前置判断。

## 成长与体貌

等级驱动三条链路（体型 / 体征解锁 / 战斗数值），数值全部集中在 `tv/growth.js`。**这是单一真源：任何第二份公式都是缺陷**，改数值只改那个文件。

### 体型

形态区间之间**分段线性插值**，区间写在 `progression.js` 的 `EPOCHS[].scale`：

    bodyScale(L) = 本档 lo + (hi − lo) × (L − 本档 min) / (下一档 min − 本档 min)
    growFactor   = 1 + 0.02×质量 + 0.03×岩浆 + 0.03×巨躯 + 突变体型加成
    finalScale   = min(1.12, bodyScale(L) × growFactor)

| 形态 | 等级区间 | 体型区间 | 锚点 |
| --- | --- | --- | --- |
| 幼兽 | 1 → 25 | 0.34 → 0.58 | L1 = 0.34、L15 = 0.48 |
| 亚成体 | 25 → 50 | 0.58 → 0.76 | L25 = 0.58 |
| 成体 | 50 → 75 | 0.76 → 0.90 | L50 = 0.76 |
| 完全体 | 75 → 100 | 0.90 → 1.00 | L100 = 1.00 |
| 灾厄体 | 100+ | 1.00（基础饱和） | 之后只靠天赋与突变 |

上限 `1.12`（`CEIL`）是渲染层约束：再大就会盖住页眉与底部新闻条。曲线上任何一级都不回落，且**每一档都有肉眼可见的增长** —— 早期版本的饱和指数在 15 级就到 0.86，观感上"只有前 15 级在长"，已废弃。

⚠️ "肉眼可见"的判据是**下面这一节的乘积**，不是 `finalScale` 本身。2026-09-18 之前这两件事是分离的：曲线每级都在涨，屏幕上却几乎看不出来。

### 屏幕表观尺寸 = 体型 × 镜头

玩家看到的不是 `finalScale`，是 **`finalScale × 镜头系数`**。只守体型会漏掉"曲线在涨、画面没变"这一类缺陷 —— 2026-09-18 实测（LV11 真实存档）：体型 +29.4%，镜头却在反向收缩，屏幕上只有 +15.5%，一级只多 3.8px，L8 换场时画面还倒退 2.9%。

    cameraScale(L) = min(1.30, 1.02 / finalScale(L))      ← growth.js 的 VIEW
    apparent(L)    = finalScale(L) × cameraScale(L)

- 镜头**不随等级主动拉远**。老实现是三项 `min`：第一项从 1.30 线性收到 1.00（正好抵消体型增长），第二项按场景硬切（1.30 / 1.16 / 1.00，换场时画面倒退 −2.9% / −7.3%），第三项因 `CEIL = 1.12 < 1.16` 永远不是最小值、从生效过 0 次。三项已全部删除。
- `1.02` 是**防溢出保险丝**，不是"越高级越远"。身体屏幕高 `401.2px × 表观 × 0.8`，地面线 `720 × 0.72 = 518.4px`，顶部字幕条底边约 185px，故表观上限 ≈ 1.038，取 1.02。它 L53 起才生效，之前镜头恒为 1.30。
- 这一项**未计入背鳍**（`BIND_BOUNDS` 是身体轮廓，背鳍由 `FinRenderer` 另画）。安全论据是相对改动前：改动前满级满突变的表观最大 1.015，1.02 只比它高 0.5%，即"不比改动前更糟"。要再收紧，先抓一张满级原生帧量出背鳍顶端。
- L50 之后表观趋近上限，怪物相对建筑不再继续变大 —— 那是屏幕物理高度决定的，不是曲线被压平。要更长，得先给顶部 UI 让位。
- 场景表 `STAGES[].camera` 已删除。镜头只允许一个真源，有断言盯着它不许回来（`tests/growth-system.test.cjs`）。

### 背鳍门禁

背鳍 15 级才出现。门槛之前是**真的没有这个部件**，不是"画得小"。

    背鳍根数 = 0                                      （L < 15）
    背鳍根数 = 2 + floor((L − 15) / 12) + 天赋 + 突变   （L ≥ 15）

即 L15 = 2、L27 = 3、L39 = 4、L51 = 5 … L99 = 9。

随机背鳍变化（脊刺增生 / 脊刺加长 / 脊刺晶化 / 脊刺分叉）同样锁在 15 级之后：突变池按门槛过滤，门槛前抽不到（过滤后若整池被清空会退回未过滤池，避免"每级抽一次"静默失效）。天赋与突变带来的背鳍加成在门槛前一律归零 —— 旧档里写着 `spikes` 也不作数，那不代表幼兽该长背鳍。

未登记的门槛一律**不解锁**。把 `spines` 写成 `spine` 不会被当成"无门槛"放行，而是判定成永不解锁 —— 门禁是对玩家的外观承诺，静默放行比报错难查得多。

### 受击范围 = 体型

受击盒由骨骼 bind pose 的包围盒算出（`rig.js` 的 `BIND_BOUNDS`），绕**脚底锚点**按同一个体型系数缩放，与渲染共用同一套缩放：

    hitbox(体型, x, 地面) = BIND_BOUNDS × 体型，锚点 (x, 地面)

底边恒等于脚底，宽度与体型严格成正比。1 级体型 0.34 时可命中高度约 136 px，满体型 1.12 时约 449 px。

弹道瞄准点与命中判定都走这个盒子，**不再有任何按满体型写死的常数**。旧实现把瞄准点写成 `G - rand(90, 280)`、命中下限写成 `G-350`，都是按满体型（约 401 px 高）定的；1 级体型只有 136 px 高，于是炮弹整片打在空中、命中盒也接不到 —— 这就是"体型小时子弹打在大体型范围"的根因。

## 敌军阻力

区域倍率 = 1 + (区域−1)×0.19。

| 类型 | 基础耐久 | 基础压制权重 |
| --- | ---: | ---: |
| 坦克 | 90 | 0.07 |
| 直升机 | 80 | 0.06 |
| 火箭车 | 160 | 0.13 |
| 重装直升机 | 230 | 0.19 |
| 电磁装甲车 | 360 | 0.31 |
| 攻城机甲 | 600 | 0.45 |

近处存活敌人的压制叠加，区域提高压制；动能等级减轻压制；不可阻挡再降低 40%。最终速度 = 基础步速 / min(3.4, 1+压制)。主街建筑和强化路口单位提供实质阻挡，必须摧毁后通过。所有伤害始终有效，区域不会要求付费或手动操作才能继续。

## 破坏状态机

车辆：alive → exploding → gone，或 alive → flying → exploding → gone。

飞机：alive → crashing/flying → exploding → gone。

`flying` 带水平抛射速度、负初始垂直速度、重力和角速度；`crashing` 带持续下坠加速度、较慢旋转、烟和火；接触地面时触发二次爆炸、邻近伤害、废墟和新闻。击破奖励仅在首次离开 alive 时结算，防止坠落再计分。

建筑死亡后按楼层错开时间，自上而下沉降、横移和偏转。尘浪、碎片、燃烧和静态瓦砾各自有生命周期。烟火、粒子和临时敌人均有数量或距离回收上限，避免长时间挂机不断占用内存。

## 存档与离线

使用版本 3 的本地存储结构；读取时校验数值、等级、技能和偏好。相同页面刷新会重建当前区域并恢复已破坏目标。固定敌人被击破后不会因刷新再发奖励。

离线核能 = min(离线秒数, 28800) × [被动产速 + 7×破坏收益倍率] × 离线效率。

离线经验 = round(离线核能 × 0.12)。折算比 0.12 取低于在线实测的 XP/核能 比（约 0.131），保证离线严格劣于在线。离线不伪造击杀、不推进城区，只有核能与经验入账。

每次结算立即更新时间戳并保存，重复结算不会再次发放同一时段的核能。后台长时间停顿采用离线结算，避免浏览器恢复后追赶数万帧。

## 新闻界面与比例

游戏与新闻框都位于 16:9 的同一容器内。画面仅常驻四个功能按钮，点击打开同尺寸管理屏；关闭后返回现场。菜单不暂停世界。全屏黑边填补剩余空间，不拉伸画面。

下方滚动条使用双份文本连续滚动，完整轮播交界时替换最新新闻，避免每次事件都从头跳动。主标题更新后先完整出现，再以每秒 24 像素横移，避免从画面外开始时被频繁新消息打断。

## 建筑耐久 · 2.2

主街 / 后排 / 前景建筑基础耐久分别为 780 / 520 / 360。耐久 = 基础值 × [1+(区域−1)×0.22] × [1+max(0,楼高−基准高度)/500]，取整；主街与后排基准高度 210，前景 90。高层楼承受更多攻击，区域推进逐步提高结构强度。建筑耐久不随玩家即时攻击力调整，保留加点后的拆楼效率提升。这里的区域系数 `[1+(区域−1)×0.22]` 与巨兽伤害**共用同一个数**（住在 `growth.js` 的 `DISTRICT.coef`），别在 `game.js` 或 `progression.js` 里再写一份 0.22。

存档保存剩余耐久与最大耐久，读取时保持损伤比例。旧存档使用原版建筑耐久推算比例，已破坏状态不变。

## 行进节奏 · 2.2

基础行进速度降低约 35%，初始速度从 59 降为 38。步态系数同步从 3.7 降为 2.9，减慢交替迈步；攻击动作时间和技能冷却保持原值。动能加点仍能提升速度和抗压制能力。

## 推图与章节 · 2.6.3

一章 5 个区域，区域编号 = 关卡编号（`doc/README.md` 写作约定第 2 条）。章名由区域派生、不单独存储：区域 1–5 大阪、6–10 东京、11+ 纽约（`progression.js` 的 `chapterFor`）。所以**跨章不是一次跳跃，而是区域 5→6、10→11 那两次推进**。

### 推进闸门

本区推进度 = `min(1, Δ建筑/12) × 0.6 + min(1, Δ敌军/8) × 0.4`，Δ 自上一次推进起算（`mapStartCleared` / `mapStartKills` 随存档落盘）：

    mapProgress() = 已开闸 ? 1
                  : min(1, max(0, cleared − mapStartCleared)/12) × 0.6
                  + min(1, max(0, kills  − mapStartKills )/8 ) × 0.4

满 1 即开闸；闸门一旦打开就锁存到这次推进完成，不会因为后续进度回落而重新关上。推进落盘时 `mapStart*` 归位到当前值，下一区从 0 重新计。

### 画面上的推图轨道

轨道与 5 个节点**画在同一条线**上（`y = 44`），节点方块压在轨道上（节点行 `x0 = 262`，`step = 125`）：

| 段 | 画法 |
| --- | --- |
| 走过的段（`i < 当前节点`） | 绿 `#70e7b0` |
| 当前段 | 按本区推进度填该区街道色 |
| 本章最后一个节点的当前段 | 改填右侧 40px 的「章末出口」，指向下一章 |
| 未到的段 | `#30445b` |
| 已开闸 | 当前节点套一圈红 `#ff7780` |
| 真的跨章（下一区已在下一章） | 右栏「下一章 · 东京」转红 `#ff7780` |

红只留给"能切场景"这一件事。同章内开闸时右栏保持灰蓝 —— 否则红色到处都是，这个信号就没了。开闸本身另有节点红圈与右下「已突破 · 遥控器进入下一城区」两处提示。

⚠️ 2026-09-18 之前这条轨道是坏的，三种表现同一个根因：进度条被单独画在 `y = 65`（**和节点不是一条线**）；填充宽度 `(w+16) × progress` **不含当前节点序号**（站在第 2 个区、本区推进 0% 时也从最左边铺开，看着像"快到章末"）；而节点之间的连线只在 `i < index` 时变绿（**正在推进的那一段永远是暗的**，即"推图指示不亮"）。

### 关卡前进按钮

按钮只在观测面板里（电视窗口自己不显示它）。文案**跨章才点名章节**，章内点名下一区街道：

| 位置 | 文案 | 状态 |
| --- | --- | --- |
| 区域 1–4（同章内） | `进入 通天阁商店街` | 闸门未开=灰 / 已开=红 |
| 区域 5 → 6、10 → 11 | `进入第二章-东京` / `进入第三章-纽约` | 同上 |
| 无下一区可进 | `进入下一张地图` | 灰、不可点 |

灰色必须由底色压出来（`background:#232e3d`），**不能只靠 `opacity`**：桌宠背后就是桌面，半透明的蓝底按钮看着"还能点"，玩家会一直点它却拿不到反馈。

### 两侧白名单是同一份契约

按钮是"遥控器"，权威状态在电视窗口里 —— 面板上的点击走 `panel:tap` → `tv:command`，最终落到电视窗口的 `panelCommand()` 执行。**两侧各有一份白名单，必须同一集合**：`tv/game.js` 的 `valid` 正则决定执行什么，`panel-preload.js` 的 `FORWARD` 决定转发什么。

只加一边就等于那个按钮不存在：点了没有任何反应，两端也都不报错。2026-09-18 的 `nextMap` 就是这么丢的 —— 推图永久停在第一章，日志里一个字都没有。`tests/tv.test.cjs` 现在从 `game.js` 的源文反推它能接受的 id，逐个断言面板放行，加操作只加一边会红。

## 成长按钮的门 · 2.6.3

加点 / 核能购买 / 掷骰进化这三组按钮能不能点，只由当前数值决定：

    加点可用     = 加点机会 > 0        且 该项等级 < 500
    核能购买可用 = 核能 ≥ 该项强化成本  且 该项等级 < 500
    掷骰进化可用 = 进化机会 > 0

判据只有一份：`tv/game.js` 的 `statGate(k)`。渲染面板与心跳共用它，不许抄第二份。

⚠️ **门必须挂在 `hud()` 的 200ms 心跳上，不能跟着"观测面板是否可见"。** 电视窗口里 `renderGrowthPanels()` 一次都不会跑：`tv-preload.js` 的 `guardMainPanel()` 用 MutationObserver 把 `#management` 永久按住 `hidden`，`hud()` 里那句重绘的守卫 `if(!$('management').hidden)` 于是恒为假，剩下的触发点只剩"某个命令成功执行之后"那一次。

后果是按钮带着**上一次成功操作那一刻**的 `disabled` 活着：用光点数被置灰 → 之后升级再把点数发回来 → 按钮仍然是灰的；而 `panelCommand()` 第一句就是 `if(!el||el.disabled)return null;` —— 面板点过来的命令被静默丢掉，**两端都不报错**。这就是"按下去没反应"。

`#buy-*`（核能购买）受害最重：核能每时每刻都在变，它几乎必然停在"买完那一刻"的灰。

判据在 `tv/tests/growth-gates.test.cjs`：门跟着数值开合（含满 500 级那一档）、`syncGrowthGates()` 必须出现在 `hud()` 里且在"面板可见"守卫之前、`statGate` 只有一份。三条都做过变异自测（删掉心跳调用 / 把门挪进守卫 / 另抄一份判据，各自都会红）。
